# Changelog

## Unreleased

First draft; the interface is not frozen.

- `Secret`, `WorkArea`, `Isolation::enter` and `write_secret`, moved from the identical copies in `mhfe_core` and `stego-core`, so that each protection is written and fixed once. `Secret::zeroed` and `Secret::as_mut_bytes` are public, and `WorkArea` is the work area a computation such as Argon2id maps.
- A child process: `Secret::is_out_of_children` and `WorkArea::is_out_of_children` report whether the system confirmed that a child gets none of the bytes (`MADV_WIPEONFORK`, `MADV_DONTFORK`, `minherit`); the copies made these calls and dropped their answers.
- Linux secret memory is opened with `O_CLOEXEC`, so that a program another thread starts in the meantime does not get its descriptor, and `fork` waits while the descriptor is open, so that a child made at that moment does not inherit it. A process takes secret memory only if it had one thread when it first made a secret or isolated itself: later, a `fork` already begun could not be held back, and its secrets lie on locked anonymous pages. A secret waits a tenth of a second for a `fork` that holds the gate, then takes such pages too, as it does where signals cannot be blocked on its thread.
- `Isolation::enter` installs its seccomp filter and its Landlock layer once per thread: a further call no longer adds a layer each time and uses up the kernel's limits. The filter is recognised by an answer only it gives, so that a filter the system or a container installed, as every Android app runs under, does not keep this crate's out.
- Landlock is built with the `landlock` crate of the Landlock project instead of hand-written system calls. It asks for the rights of Landlock's ABI 9 (Linux 7.1) and leaves out on an older kernel those it does not know.
- Landlock also refuses a connection to an abstract UNIX socket made outside the layer (from Linux 6.12) and to a UNIX socket by its path (from Linux 7.1), which a socket opened before could make as it could make a TCP connection.
- `Isolation::enter` on Linux also refuses what a probe of the channels found open: System V IPC, POSIX message queues and the keyring, which other programs of the user reach by key or name; `connect`, `bind`, `listen`, `accept`, `sendmmsg` and `sendto` with an address through sockets opened before; `execve`; `process_vm_readv`, `userfaultfd`, `bpf`, `perf_event_open` and the newer mount calls; and the `prctl` options that would make the process readable again. Landlock refuses signals to processes outside it (Linux 6.12). A process of one thread gets user, network and IPC namespaces of its own, asked for in one call: a system that restricts user namespaces, as Ubuntu does, refuses a second call in the new one.
- Speculative store bypass and indirect branch speculation are disabled for good on Linux and Android (`Isolation::speculation_limited`), and side-channel isolation is set on Windows. Where the kernel gives a program no control of one of them, as Linux on AArch64, the answer is unknown, not limited.
- A filter or Landlock layer the system refused is no longer recorded as installed: the next call tries again. A layer that was refused is not reported as a signal scope because the filter went in, and one that goes in at a later call is recorded by one more filter.
- Each protection has an `Outcome`: confirmed, refused, not requested, not offered on this system, or unknown (`Isolation::outcome`). `Isolation::measures` gives each protection's outcome, its reach and what the call observed for that outcome; a protection that was refused or not asked for never carries the proof of one that holds.
- The answer of `Isolation::enter` does not overstate: `no_memory_reading` is refused when a tracer is attached to any thread (Linux) or a debugger is present (Windows) and unknown when the threads cannot be listed; `no_file_changes` is not offered on Windows and refused on Linux without the filter; `no_core_dumps` is not offered on Windows; a list of threads that cannot be read is no proof of a process of one thread. On Linux and Android a refused probe of sockets, programs, file locks or `sendmsg` confirms only together with this crate's filter and its rule: refused by someone else's policy alone, it reads as unknown. In a PID namespace of its own, where a debugger outside it does not show, the reading of memory is unknown.
- `Isolation::no_new_programs`: no other program can be started. The filter refuses `execve` on Linux and Android and the child-process policy holds on Windows, each checked; on macOS the sandbox allows it to no one, which no probe confirms yet, so it reads as unknown.
- Windows: the default search for a DLL covers only the program's folder and System32, which a call with a path or search flags of its own still leaves; extension points, remote and low-integrity images and child processes are refused, the last without the exception for secure processes; a job refuses writing the clipboard, global atoms and other processes' windows and allows one process; the process runs at low integrity. Each is checked and has a field of its own: `no_new_programs`, `no_planted_libraries`, `desktop_restricted`, `low_integrity`.
- macOS: the sandbox refuses everything but what a secret command needs, by least privilege; a refused probe counts only with this crate's profile in place, a debugger is refused before the sandbox is entered, and of two calls at once the second finds the first one's success.
- Every buffer lies between guard pages. Linux marks anonymous pages unmergeable and asks the kernel to keep a secret's on small pages, since it copies pages when it joins them into a huge one; a work area keeps the huge pages the system gives it.
- `Secret::locked` and `WorkArea::locked` refuse pages the system did not lock, before a secret is put in them. `ClosedSecret` keeps its pages closed between uses and remembers what they allow when the system refuses a change.
- `Options` turns on what may keep a usual program from working, off by default: refusing file locks and `sendmsg` (Linux, Android), no new executable code and only DLLs signed by Microsoft (Windows), each read back in `Isolation`. No new executable code counts only when no thread or other process can lift it. `Isolation::enter_requiring` and `Isolation::require` stop before a secret when a required `Protection` is not confirmed.
- `Options::signals_to_self_only` and `Options::lock_all_memory`, each tied to the process that asked: a child made by `fork` does not report its parent's, and the filter itself answers, to the thread that asks, whom its signal rule names: no thread reports another thread's rule, and a child that asks gets a filter of its own. The lock's mark lies on a page that a child gets as zeros, so that a child with its parent's number in another PID namespace does not report it either; where the system gives no such page, an earlier lock reads as unknown. `Isolation::signals_within_layer` reports the signal scope of the Landlock layer apart from the option.
- `Worker` and `serve`: the secret work in a process of its own. What the worker inherited is closed before its `main` starts, so that `serve` closes nothing of the program's own; a text in the worker's variable that is no setting closes nothing. On Linux and macOS a worker that holds a descriptor besides its standard streams when it comes to `serve`, inherited or its own, says that its start was not clean. Before it reads anything, the worker leaves the terminal, isolates itself and reports; the parent sends a request only after a clean start with every required protection confirmed (`WorkerError::Unclean`, `WorkerError::Missing`). `serve(most, answer)` bounds a request, runs once in a process, takes only a setting written exactly as a parent writes it, and ends the worker's streams when it returns, so that a worker which lives on does not keep its parent waiting. A failed call ends the worker before it returns. Ending a worker gives it a second, then kills it and waits a second more, so that neither side waits for the other for ever; `Worker::end` says whether it ended, since a program that may not signal other processes has to leave it behind; a worker is ended once, whoever asks. The worker is started from a thread with an ordinary stack, whatever stack its caller runs on, and a worker starts no worker, so that a program which reaches `Worker::start` before `serve` does not start itself without end. On Windows the worker runs in an AppContainer without capabilities and inherits no handle: it opens a pipe by name, and the parent takes the connection only from the process it started; another process of the user that takes the pipe first gets nothing and is put off, while the worker keeps trying its pipe for a second.
- `open_channels` lists what is still open after isolation: each descriptor's kind, whether it is open for writing, and whether the list is complete.
- `run_on_protected_stack` runs secret work on a thread whose stack is protected and wiped, the bytes no frame wrote included. It takes the properties the stack must have and does not start the work without them.
- `SecretLine` and `Keystroke`: a password typed in a window, collected one key at a time in protected pages; `Keystroke::to_bytes` gives bytes that wipe themselves.
- Windows: the working set is read and set again as one step, so that threads that make pages at once no longer lose a change and every later drop gives back only what was taken. A work area is locked whenever Windows takes the lock, whether or not the working set grew.
- macOS: the probe of file writes makes only a new file and removes only what it made; the copies could truncate a file or the target of a link at a predictable path.
- WebAssembly: a work area the allocator cannot give is refused instead of ending the program.
