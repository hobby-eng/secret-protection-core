# Changelog

## 0.2.0 (2026-11-26)

### New features

- `Worker::start_within` and `Worker::call_within` take a deadline. When it passes, the start or call fails with `TimedOut` and the worker is given up, terminated where a stable handle exists (Windows, Linux with a pidfd), so a worker that stops answering no longer blocks its parent for longer than the deadline and the shutdown wait. `start` and `call` keep waiting without a deadline.
- `Isolation::enter_requiring_process_wide` and `Isolation::require_process_wide` require each listed protection, and `WholeProcess`, to cover every thread, the rule a worker is admitted by. `Missing` from them lists every unmet protection.
- `with_cleared_stack` and `clear_stack` overwrite 128 KiB of the calling thread's stack below the caller's frame after secret work, for computations whose dependencies leave their state on the stack, such as the lanes of a password hash.
- `read_hidden_line` reads a line typed on a terminal (Unix) or console (Windows) into a `SecretLine`, shows none of it and says how the line ended (`LineEnd`). Echo, the terminal's own line editing and its signal keys are off while it reads, as the terminal reports back, and restored after, a failed restore being an error. Input waiting when the reading starts or left when it ends, up to 64 KiB, is dropped, and the 16 KiB of stack below it are wiped. It uses only the standard streams the process holds, so an isolated worker on the terminal reads the line itself.
- `WritableFolder::create` makes a new private folder before isolation, and `Isolation::enter_with_folders` lets the program write beneath it and nowhere else (`Protection::FolderWrites`): on Linux a Landlock rule beneath each folder, and a filter that then lets new files of mode 0600, folders of mode 0700, links, renames and removals through and still refuses every other change; on macOS a sandbox rule beneath the folder. A folder is granted only while it is still the one made and empty, and only by the first isolation.
- `OpenChannels` lists the shared memory the process can write (`shared_mappings`), a way out with no descriptor, and `OpenChannels::only` refuses unless the inventory is complete and holds only the named descriptors and no such memory. `OpenChannels` has a new public field.
- `Options::all_threads` puts the Landlock layer from Linux 7.0, and with it the seccomp filter, on every thread of a process that already has other threads when it isolates itself (TSYNC), so that each protection they enforce reaches the whole process; each measure's reach and `whole_process` say how far they went. Below Landlock ABI 8 both stay on the calling thread, as the filter's rules count on the layer; a kernel without Landlock puts the filter alone on every thread. The layer's TSYNC is tried once per process, after a filter allowing everything, put onto every thread first, showed that no thread holds a seccomp filter of its own; otherwise the whole call stays on the calling thread, while a later call may still put the filter alone onto every thread. Linux isolation calls run one at a time.
- Intel macOS (`x86_64-apple-darwin`) is a supported target, and CI runs the tests there, as it now does on Windows with the GNU toolchain and for WebAssembly in Node. 32-bit Linux stays a test, not a supported platform; Android and iOS are built and linted, with no runner testing them yet.

### Breaking changes

- On Linux no worker starts unless Yama's `kernel.yama.ptrace_scope` is 1 or more and the program runs in the first user namespace: from `exec` until its isolation the worker is dumpable, and in a user namespace its user owns it stays open to the user's processes after it too, so its report would prove nothing. Every start fails first with `WorkerError::Start` of kind `PermissionDenied`. `NoMemoryReading` of a program started in a user namespace reads `Unknown`.
- The Linux filter also refuses `prctl(PR_SCHED_CORE)`, whose cookie can be shared to and from other processes.
- On macOS `NoMemoryReading` is confirmed only when the program's code signature has the hardened runtime and not `get-task-allow`, which also keeps `task_for_pid` out; `PT_DENY_ATTACH` alone stops only `ptrace`, so without that signature it reads `Unknown`.
- On Windows a process's access list no longer grants its user `PROCESS_QUERY_LIMITED_INFORMATION`, with which another process of the user opened its token and changed the default list of the threads it starts later.
- A Windows worker runs in a less privileged AppContainer, without ALL APPLICATION PACKAGES (`S-1-15-2-1`): its program file and the libraries it loads must let ALL RESTRICTED APPLICATION PACKAGES (`S-1-15-2-2`) read and run them, as Program Files and System32 do, and files, registry keys and services open only to ALL APPLICATION PACKAGES are closed to it.
- `OpenChannels` has a new public field, `shared_mappings`, and is `#[non_exhaustive]`: code that builds it with a struct literal or matches it without `..` no longer compiles. Read its fields, or call `OpenChannels::only`.
- On Linux a worker with another thread at its start is refused as unclean (`WorkerError::Unclean`), as that thread may hold a descriptor table of its own; before, it was refused for `WholeProcess`, or admitted after an earlier call had put the filter on every thread.
- On Windows `ClosedSecret::locked` keeps its pages locked and open, and `is_closed()` is false: Windows unlocks a page it makes inaccessible, and the page file can then take it. `ClosedSecret::with_capacity` still closes its pages, and `is_locked()` is false from the first closing. Before, a closed secret reported a lock it no longer held.

### Changes

- On Windows the worker process and its first thread are created with their restricted access lists. Before, they had the default lists until the worker isolated itself, and another process of the same user could open the worker in that interval. A worker also starts suspended, and runs only once its token's default list keeps the threads Windows starts in it before its census, such as the loader's, as closed. It has no console any more, and its child-process, extension-point and image-load policies are set when it is created, not by the worker after its start-up code.
- Every Unix worker leaves its parent's session, the one on the terminal too, so no worker can type into the shell through a controlling terminal (`TIOCSTI`). `start_on_terminal` now gives the worker this program's terminal, opened anew for reading and writing, as its standard error, or `/dev/null` without one, never a socket or file the parent's standard error points to; `/dev/tty` no longer opens in it. A worker that cannot leave the session is not clean.
- The macOS sandbox writes data only to `/dev/null` and the process's own terminal, without mode or owner changes, allows ioctls only on that terminal and refuses reading the user's other terminals. It used to allow every write and ioctl on every terminal.
- Linux clears the dumpable flag and the core limit before entering the user namespace. Before, another process of the user could open the process's memory in between.
- The Linux filter limits resource limits, scheduling, page placement and robust-list reads to the process itself and refuses `kcmp`, `process_madvise` and `ioprio_set`. `signals_to_self_only` also refuses the `fcntl` owner commands, and `refuse_file_locks` refuses leases.
- Protected stacks on Linux ask for small pages, as secrets do. Linux starts a worker from `/proc/self/exe`.
- A Unix start with a deadline also bounds the wait for the launch. A deadline too far ahead for the clock to hold waits without one, as the documentation now says.
- On macOS a process whose standard streams are not terminals gets no terminal rule at all, `/dev/tty` included, so it cannot type into a controlling terminal.
- A worker reuses one request buffer, wiped after each request, instead of making a new secret for every frame; on Windows a call with a deadline starts one watchdog thread instead of four.
- Linux enters its user namespace only when the cleared dumpable flag reads back. `signals_to_self_only` also refuses `F_SETSIG` and setting `O_ASYNC`, after which a terminal would name its foreground group as the owner by itself; `refuse_file_locks` also refuses delegations (`F_SETDELEG`). Calls on a process accept only 0, the caller, so that a child of `fork` cannot name its parent.
- On Windows a start or call with a deadline goes by the clock: work that ends past the deadline fails, and the launch checks the deadline before and after the calls that cannot be cut short. A Unix launch that finishes after its start gave up is ended through its stable handle.
- The macOS sandbox keeps reads off every terminal device but the process's own.
- Linux counts a process's threads by the kernel's own count in `/proc/self/status`, and a tracer check that listed fewer threads than that is unknown. The filter's private marks belong to the 0.2 line, so a filter of 0.1 that another dependency of the same program put in never counts as this version's.
- `with_cleared_stack` also clears the stack when the work panics and unwinds, writes the zeros once, and keeps the work below a cushion of unwritten stack, so that the clearing reaches the top of its frames. WebAssembly clears nothing, as the crate cannot tell how much of its stack is left below the work.
- `read_hidden_line` reads the terminal's settings back after restoring them and fails when they differ, or when the input waiting before or after the reading could not be dropped; the restore comes before the closing line break, and its error wins over the reading's. It never sets the two bits the terminal changes by itself, `PENDIN` and `FLUSHO`: output a Ctrl+O was dropping shows again, and the read-back passes over both, as macOS sets `PENDIN` itself when line editing comes back on. On Windows a console that cannot drop its waiting input is refused, and the mode is read back after the restore. A mouse report at column or row 95 no longer counts as Backspace.
- `WritableFolder::create` checks the folder made before it changes its mode, and on a failure removes it only while it is still that folder. On macOS `is_private` is false when an access list on the folder or above it allows anything to anyone, when a volume is mounted to ignore owners, or when someone else could move the folder or a folder above it, as the sandbox grants a folder by its path.
- The macOS channel check counts writable memory whose writes reach a file or another holder, and memory a child of fork would share. The program's own data segments and an allocator's guard pages no longer count, and the `os_log` buffer that isolation brings in is left out when one region alone looks like it. An error of the region walk other than its end leaves the inventory incomplete. The macOS file probe runs outside the granted folders, under a name no other user can guess, and the process's own terminal may have dots, dashes and underscores in its name.
- A Unix worker start checks its deadline again just before each launch attempt, after the lookup of `pidfd_spawn` too. On Windows the wait for the worker's pipe checks the deadline and the worker on every turn, also after another process was put off.
- With file changes refused, the Linux filter also refuses `F_SET_RW_HINT` and `F_SET_FILE_RW_HINT`. A child of `fork` no longer leaves out of the channel check memory its parent recorded as its own secret memory.
- A work area never lent for writing is given back untouched instead of wiped: it still holds the zeros the system made, and filling in its pages brought a large unused reservation, such as one whose computation never started, into memory.
- On 32-bit Linux the check that `sendmsg` is refused passes its arguments as machine words; it passed 64-bit values, which that system reads as other arguments.
- On Windows `enter` sets and reads the access list of the calling thread through its pseudo handle. A worker in its AppContainer could not open its own first thread, which starts with the restricted list, so its memory would have read as open to others and the worker would have been refused. `write_secret` takes a character device that refuses `GetConsoleMode` for want of the read right for a console too, so a console open only for writing gets UTF-16.
- On macOS `WritableFolder::is_private` is also false when a symbolic link on the folder's path belongs to someone else or lies in a folder someone else may change, and an access-list entry of any kind but deny counts as allowing. The file-write probe passes over a temporary folder that does not exist instead of reporting file changes as allowed. `WritableFolder::create` drops a final `/` or `/.` from its path, after which the check of the path would follow a link.
- `read_hidden_line` also turns off flow control (`IXON`) and the input changes that drop Enter (`IGNCR`) or the eighth bit (`ISTRIP`), refuses an input set not to wait (`O_NONBLOCK`), takes no descriptor open only for `ioctl`s, and does not drop input a second time after a failed first drain.
- With `Options::all_threads` a fork on another thread waits until the Landlock layer is on every thread and recorded, where an earlier call put the gate of secret memory in place and it is free within 100 ms. On Linux with a pidfd a worker that ends by itself just as its shutdown wait runs out counts as ended. `run_on_protected_stack` rounds the system's least stack size up to whole pages, the `Debug` text of a `WorkArea` no longer reaches its pages, which ended a child of `fork`, and a worker gives back its request buffer before it takes a larger one.
- On Linux a worker's standard input and output are two pairs of connected sockets instead of pipes: another process of the same user could open the parent's pipes again through `/proc/PID/fd`, and read or change requests, answers and the startup report; it cannot open a socket so. The channel stays as private as the parent, which a process allowed to attach to it can still read.
- A size whose pages would span more than `isize::MAX` bytes, the most a Rust slice may, is no longer mapped, though a 32-bit system could map it: work areas and protected stacks refuse it, and a secret of that size ends the program, as a size the system cannot map does.
- On Unix an exchange with a worker that ends past its deadline fails with `TimedOut` when it failed for another reason too, as on Windows. `Worker::start_within` answers `Unsupported` on WebAssembly instead of reading a clock that is not there.
- After a reading that ended as it should, `read_hidden_line` drops the input that arrived after its last drain with `tcflush` just before it puts the terminal's settings back, never with `TCSAFLUSH`, which first waits until all output is sent. A key typed between the two calls goes to the next reader, as documented. The Linux filter lets that flush through, `TCFLSH` with `TCIFLUSH` alone.
- A line typed on past its capacity counts the extra keys with a checked addition: a count that would leave the range of `usize` refuses the line with `InvalidInput`, where it could overflow on a 32-bit system.
- On Linux, when the launcher needs a descriptor table of its own and starts a thread for it, `Worker::start_within` checks its deadline there too, just before the launch, and again before it falls back from `pidfd_spawn` to `posix_spawn`.
- A request or an answer longer than a `Secret` can hold on the system is refused before anything is allocated, whatever the caller's limit: on a 32-bit system such a frame used to end the program.

### Build and verification

- A release is built only after the tests on every platform, the dependency audit and a short fuzzing run pass for the tagged commit.
- `THIRD_PARTY_NOTICES.md` names the versions in `Cargo.lock`, which CI now checks. In 0.1.1 it still named zeroize 1.9.1 and landlock 0.4.7.
- CI checks that `THIRD_PARTY_NOTICES.md` names exactly the packages of the library's dependency tree with their complete versions; the fuzz workspace pins `libfuzzer-sys` exactly, and a release fuzzes only with the checked-in fuzz lockfile, before and after.
- CI runs the stack-clearing tests in the release profile on Linux x86-64 and ARM64, macOS and Windows; the tests read the stack through the system on each.
- CI runs the terminal tests under `strace` on Linux and fails on any terminal change that waits for output (`TCSADRAIN`, `TCSAFLUSH`, `tcdrain`), which a test terminal, holding no output, cannot show by itself; for macOS, which has no `strace`, it reads the source for such calls.
- CI checks the formatting of the Markdown, JSON, TOML and YAML, and lints a 32-bit Linux without this crate's filter.
- CI runs the tests on Intel macOS, on Windows with the GNU toolchain as well as MSVC, and on 32-bit x86 Linux (`i686`) for the 32-bit sizes, and runs the WebAssembly checks of `wasm/` in Node. 32-bit Linux, like the 32-bit ARM target CI lints, is a test, not a supported platform. Android and iOS, the simulator on Apple silicon included, are compiled and linted, and the README says that no runner tests them yet.
- A release runs every fuzz target for 90 seconds before it packages; the tag also starts a 30-minute campaign of each target on GitHub (`fuzz.yml`), which the release does not wait for.
- Three more fuzz targets reach what crosses into the process: `frames` (the worker's requests and the parent's answers), `roster` (the thread list of a Windows worker's census) and `editor` (UTF-8 and UTF-16 input through the line editor); `report` reads the clean-start flag too, and `setting` the Windows channel. The readers they reach are the ones the program runs, moved into functions of their own.

## 0.1.0 (2026-11-15)

### Memory and input

- `Secret` holds bytes at a fixed capacity. `Secret::zeroed` and `as_mut_bytes` let an application fill the buffer directly. `WorkArea` provides zero-initialized scratch space for computations such as Argon2id. Both types wipe their storage on normal drop in the owning process.
- `Secret::locked` and `WorkArea::locked` return an error if the allocation cannot be locked. Native buffers have guard pages. On Linux the library requests small, unmergeable anonymous pages for secrets and leaves the work area's page size to the kernel. WebAssembly can return `None` for an allocation that `WorkArea::new` cannot satisfy.
- `ClosedSecret` restricts page access between callbacks. `is_closed()` reports whether closing succeeded. `run_on_protected_stack` checks the requested stack properties before starting the thread and wipes the stack after it exits.
- `SecretLine` collects typed characters in a fixed-capacity buffer. `Keystroke::to_bytes` produces a frame that wipes its bytes on drop. `write_secret` writes directly to standard output after flushing buffered output.

### Forks and process isolation

- Unix allocations remember which process owns them. An inherited owner reports its protection flags as false, skips the parent's mapping on drop and aborts on fresh byte access. `is_out_of_children()` reports whether the OS excluded the contents from a fork. Borrowed slices and active protected stacks have separate [fork requirements](SECURITY.md#memory-and-copies).
- On Linux, kernel secret memory uses a close-on-exec descriptor and coordinates with `fork` while that descriptor is open. If setup happened too late in a multithreaded process, signals cannot be blocked, or the fork gate stays busy for 100 ms, the allocator falls back to anonymous pages.
- Each isolation measure reports its outcome, scope and evidence. `Isolation::enter_requiring` lets an application stop before reading input when a required measure is unconfirmed. `open_channels` lists the open descriptors it could inspect on Unix and indicates whether the list is complete. Windows and WebAssembly return an unsupported error.
- On supported Linux architectures and on supported Android native threads, the syscall filter restricts new sockets, program execution and operations through existing descriptors. Optional rules restrict file locks, `sendmsg` and signals. Linux can also lock process memory, apply Landlock rights through ABI 9, and request user, network and IPC namespaces together. A connected socket may remain usable. Failed filter or Landlock setup can be retried.
- Linux and Android check both supported kinds of speculation. A CPU that needs no mitigation can confirm the measure. When the kernel exposes too little information, the result can be unknown. On Linux, a tracer outside a PID namespace can be invisible. A denied probe alone cannot confirm that the crate installed its own filter.
- On macOS, the library requests debugger protection before entering the sandbox. File and socket probes count as confirmation only with the crate's profile in place. The file probe uses exclusive creation, then tries to unlink the probe path if creation succeeded.
- On Windows, the library reads back the process and thread access controls, token integrity, job limits and supported mitigation policies. Options can restrict dynamic code and require Microsoft-signed images. The default DLL search uses the application directory and System32. Working-set updates are serialized, and a work area reports a successful lock even when its working set did not grow.

### Workers and verification

- `Worker::start` and `serve` run secret operations in a separate process. Unix workers close inherited nonstandard descriptors before the executable starts. Windows workers start in an AppContainer without inheriting handles. The parent and worker authenticate the local pipe connection before exchanging thread lists and the startup report.
- On Windows, a standalone check reports `Unknown` when it needs a thread list the OS withholds. During worker startup the parent supplies fresh lists. The worker can read a live thread's token through the handle it acquired before tightening access. The parent keeps only wait and termination rights on the worker process.
- A failed exchange closes the transport. Linux can terminate a worker through a pidfd acquired at spawn. The Unix fallback uses cooperative shutdown and collects a late exit. `Worker::end` tells the caller whether the worker ended within the shutdown deadline.
- Three fuzz targets cover worker settings, the isolation fields of startup reports and encoded keystrokes. The Linux coverage run includes the integration programs and their worker processes. The tests distinguish a skipped subcase from one that ran. [Coverage](docs/COVERAGE.md) · [Audit history](docs/audits/README.md)
