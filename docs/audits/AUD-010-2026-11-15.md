# AUD-010 — Release audit of secret-protection-core

## Release decision

**FAIL for unrestricted production use.** The audited object is signed Git commit `39e462e946cc300a8a3d3e145517957094eb7c8c`, tree `937e813cc30dd17e1ed2174cd3caa82040a43b16`, package version 0.1.0. A Unix child that continues after fork can retain buffer owners and references to pages the OS has omitted or unlocked. This is consequential for an embedding application with inherited buffers. No parent-secret disclosure was observed.

The review covers all 73 tracked files, the public operation groups and all 32 procedure checks. The [JSON companion](AUD-010-2026-11-15.json) carries per-file hashes, public declarations, licenses and the status of 55 earlier findings. The coordinator, three subsystem reviewers and a separate completeness reviewer used the existing checkout. Model and reasoning settings were not retained. Reviewed on 2026-11-15 UTC.

The old audit already flagged the consumer risk in an unnumbered note. This report promotes it to a blocking finding and follows the implicit destructor and borrowed-view contracts. See [AUD-001, integrator guidance](AUD-001-2026-11-15.md). A child that immediately replaces its program image or exits without touching Rust objects is outside that failure path.

## Findings

### AUD-010-SEC001 — A continuing Unix child inherits buffer owners after the OS removes or unlocks their pages

On Linux DONTFORK secret mappings and Darwin VM_INHERIT_NONE memory, the child keeps the Rust pointer/length while losing the data mapping. A read or automatic drop can form a slice over absent memory. If the address is reused, cleanup can touch unrelated child memory. On anonymous Linux WIPEONFORK pages, bytes become zero but cached is_locked can stay true after the lock is lost. A single-threaded application continuing after fork with a live object can suffer undefined behavior or put new child data on unlocked pages. ClosedSecret and SecretLine wrap Secret. Darwin WorkArea also omits the pages. Ordinary immediate exec or _exit has a separate lifetime. No disclosure of a parent secret was observed. This blocks an unrestricted production guarantee.

Settle the supported fork contract for consumers and their borrowed slices. Provide a child-safe memory/ownership design for supported continuation, including release and lock reporting. Until then keep such owners and all issued views out of continuing children. Explicitly document the boundary in the API. Verify destruction, fresh child use, and lock evidence across the supported mapping types on Linux and macOS, including the documented rule for pre-fork borrowed views and a fresh-image control.

Affected locations. `src/os/linux.rs:80`, `src/os/unix.rs:219`, `src/os/unix.rs:101`, `src/os.rs:149`, `src/os.rs:153`, `src/protect.rs:108`, `src/protect.rs:151`, `src/protect.rs:218`, `src/protect/closed.rs:117`, `docs/audits/AUD-001-2026-11-15.md:383`. [Platform contract 1](https://man7.org/linux/man-pages/man2/fork.2.html) [Platform contract 2](https://man7.org/linux/man-pages/man2/madvise.2.html) [Platform contract 3](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/minherit.2.html) [Platform contract 4](https://doc.rust-lang.org/std/slice/fn.from_raw_parts_mut.html#safety)

### AUD-010-SEC002 — The ELF worker initializer can close descriptors already owned by a linked library

The executable uses an ordinary init array for bulk descriptor closure. ELF initializes dependent shared objects first. A normal dependency can therefore own an open file before this code closes it. The later descriptor scan cannot observe a descriptor already closed. Ordinary native integration can lose a live descriptor or later use or close a reused number. The main-time descriptor regression covers a different ordering. This is a separate variant of AUD-006-SEC001.

Arrange inheritance cleanup at the spawn/exec boundary, then validate the new image without closing descriptors its dependencies own. Check a representative native dependency with legitimate pre-main initialization and the current tests for inheritance and late service.

Affected locations. `src/os/unix.rs:333`, `src/os/unix.rs:349`, `src/os/unix.rs:375`, `src/os/unix.rs:390`, `tests/worker.rs:491`. [Platform contract 1](https://gabi.xinuos.com/elf/09-dynamic.html#initialization-and-termination-functions)

### AUD-010-API001 — Windows strict socket reporting describes a stronger guarantee than its evidence

The public measure states socket creation is prohibited. Windows derives it from a capability-free AppContainer token. A native stock worker enforces the required token-based measure. A caller can interpret the result as proof that every socket object creation fails. No network transfer or successful connection was observed in this review.

Describe the Windows guarantee as the applicable network capability policy, or provide separate evidence for the stronger primitive. Align strict-mode and measure descriptions and test the precise native Windows property being advertised.

Affected locations. `src/protect.rs:246`, `src/os/windows.rs:342`, `src/os/windows.rs:383`, `src/os/windows.rs:884`, `tests/worker.rs:294`, `docs/audits/AUD-001-2026-11-15.md:382`. [Platform contract 1](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)

### AUD-010-BLD001 — The secret-memory fork tests can count a failed fork or wait as success

One test ignores waitpid’s return. The 2,000-iteration test compares waitpid with child without requiring a positive child. Both can be -1 with a zero-initialized status. The descriptor scan also covers only numbers 3 through 63. A resource-limited runner can overstate completed checks. No evidence indicates that the reviewed CI actually failed to create a child. AUD-006-BLD001 addressed another test.

Require a positive PID and a successful wait for exactly that PID. Account for interruptions and report the number and descriptor range actually tested. Verify failure/skip reporting and require all claimed child observations.

Affected locations. `tests/secret_memory.rs:389`, `tests/secret_memory.rs:394`, `tests/secret_memory.rs:434`, `tests/secret_memory.rs:442`, `tests/secret_memory.rs:456`.

### AUD-010-BLD002 — Test summaries count some skipped conditions and empty platform tests as passed

Child roles can return early on Linux and the successful child’s diagnostic is discarded. The worker option test registers everywhere but its substantive body is Linux-only. Neither aggregate counts nor native green badges establish those specific namespace, Landlock retry or non-Linux option checks. The Windows and macOS jobs do contain other substantive tests.

Propagate skipped outcomes into the test summary and register tests only on applicable targets. Show separate passing, skipped and inapplicable counts on the affected jobs.

Affected locations. `tests/isolation/linux/roles.rs:169`, `tests/isolation/linux/roles.rs:210`, `tests/isolation/linux.rs:514`, `tests/isolation/main.rs:264`, `tests/worker.rs:266`, `tests/worker.rs:377`.

### AUD-010-BLD003 — The Windows competing-client regression can count a different instance

The test matches names by a common pipe prefix and counts all successful opens. A concurrent instance of this application can satisfy the counter. A false pass or disturbance to an unrelated test instance is possible. The genuine round-trip on Windows is covered separately.

Coordinate the exact synthetic worker instance with the test and scope its counter to that instance. Run isolated and concurrent test instances and verify separate attribution.

Affected locations. `tests/worker.rs:543`, `tests/worker.rs:565`, `tests/worker.rs:575`.

### AUD-010-BLD004 — Worker timing tests confuse wall-clock pauses with backend behavior

The test worker lingers for four wall-clock seconds. Other checks impose wall-clock limits. Two first local runs failed at different assertions in this group under the capped scheduler. Run 4 passed on both Linux runners. A delayed process can finish naturally before the assertion that assumes it still lives, or a measured second can include a long suspension. The local failures do not establish that a disallowed signal succeeded.

Use explicit lifecycle synchronization for the stubborn-worker scenario and separate behavioral checks from timing under resource constraints. Compare normal and suspended scheduling with the stock grace bound and record failures independently.

Affected locations. `tests/worker.rs:144`, `tests/worker.rs:446`, `tests/worker.rs:603`, `tests/worker.rs:667`, `src/os/unix.rs:295`.

### AUD-010-DOC001 — The all-platform buffer table promises guard pages in WebAssembly

WebAssembly uses an ordinary boxed heap buffer. The table claims all buffers have guard pages. A consumer can rely on a memory boundary unavailable in WebAssembly. Wiping remains implemented.

Separate the all-platform wipe guarantee from native guard pages in the summary and rustdoc. Compare the summary against the implementation and WebAssembly public-API checks.

Affected locations. `README.md:46`, `README.md:54`, `README.md:103`, `src/protect.rs:47`, `src/os.rs:272`.

### AUD-010-DOC002 — Windows Error Reporting heap exclusion is presented as assured

WerSetFlags(NOHEAP) returns HRESULT. The implementation discards it and does not read back the process flag, while the public field description says the heap is excluded. Callers cannot know whether process-wide exclusion succeeded. This is independent of the separate per-region WER capability and of arbitrary dump generators.

Qualify the documentation as best effort, or report the effective WER flag separately after checking the result. Verify both success and refusal with native Windows API evidence.

Affected locations. `src/protect.rs:236`, `src/os/windows.rs:280`, `docs/TECHNICAL.md:86`. [Platform contract 1](https://learn.microsoft.com/en-us/windows/win32/api/werapi/nf-werapi-wersetflags)

### AUD-010-DOC003 — Third-party notices omit the Windows linkage dependency

windows-sys 0.61.2 depends on windows-link 0.2.1. The manifest bundled with that version declares MIT OR Apache-2.0. The notices omit it. The release inventory is incomplete for Windows. No conclusion about legal compliance was drawn.

Add the exact package, version and license to the notices. Compare the published inventory with all unique locked package/version pairs.

Affected locations. `THIRD_PARTY_NOTICES.md:3`, `Cargo.lock:119`, `Cargo.lock:130`.

### AUD-010-DOC004 — The historical audit index and two source links need corrections

Two AUD-001 links use a tests/isolation.rs path absent at the audited HEAD. Their lines exist at the published old snapshot. The AUD-009 index entry describes closing descriptors outright although the current implementation retargets them. Readers cannot follow the old links from HEAD or reliably infer current cleanup behavior from the index.

Add dated errata linking the original commit and describe the current mechanism in the index. Preserve historical source records. Resolve every published source link and compare the amended current-status note to the cited implementation.

Affected locations. `docs/audits/AUD-001-2026-11-15.md:271`, `docs/audits/README.md:94`, `src/os/unix.rs:615`.

## Confirmed improvements

The Windows worker creates non-inheritable handles, starts with bInheritHandles false, checks the OS peer PID before admission and owns the client file through RAII. A normal native exchange succeeded in run 4. The first competing-client test was executed, with the attribution limit in BLD003. Repeated same-user contention remains a documented accepted availability risk.

The Apple initializer declares the section type. The macOS native job exercised inherited descriptors and the clean-before-serve decision. An independent external process memory-read denial on macOS was not demonstrated by the stock integration suite.

Linux records signal ownership from the calling thread’s installed filter. The fork gate refuses kernel secret pages when signal masking fails. The process-wide unmarked memory-lock outcome is conservative. Fallback-path availability and strict Unsupported/Unknown outcomes are deliberately distinct.

Fixed-capacity append, truncation and wiping, strict lock constructors, closed-secret access restoration, stack-property admission, worker bounded frames, orderly teardown under normal resources, and the fallback heap contract were traced through their public entries. Retained historical tests belong to their old snapshots unless explicitly cross-checked.

## Remaining limits

The exact pinned Rust 1.99.1 was used. Rust 1.99.0 was not separately exercised. No runtime test on an Android or iOS device, no browser UI/runtime integration acceptance and no downstream Reed–Solomon algorithm audit. The WebAssembly exercise uses V8/Node. A Windows/macOS native runtime was available through published CI, not on the Linux audit host.

The points about post-fork mapping ownership, loader constructor order and platform guarantees are supported by source and primary platform contracts. No secret disclosure or attack execution was observed. The high finding concerns continuing Unix children; ordinary spawn with immediate exec has a different lifetime.

Historical mutation, performance trials and earlier adversarial harnesses were not replayed. The exact source trees, reports and individual earlier evidence remain identifiable. Native sanitizer/Miri scopes, excluded tests and target-specific limitations are recorded per job.

There is no release tag, published binary, registry package or canonical bit-for-bit artifact acceptance procedure in this Git-only draft. The native library has a local SHA-256; binary reproducibility against an independent build was not established. A remote signature and branch identity apply to source, not a registry artifact.

The official GitHub CI and local test counts are reported separately. Skips hidden behind successful custom subprocesses and empty target-specific bodies are explicitly tracked. Timing assertions use wall clock and can fail while the host job is paused. A passing retry cannot establish the cause of an earlier failure.
