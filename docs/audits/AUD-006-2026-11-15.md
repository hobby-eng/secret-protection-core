## Historical issues still open

### AUD-001-SEC004 — Windows worker pipe ends are briefly inheritable by unrelated launches

Windows still marks the worker pipe ends inheritable across CreateProcessW. The crate lock does not serialize other process launchers in the host. Scope the guarantee or redesign the launch and verify on native Windows. This remains high severity for concurrent inheriting hosts.

Frozen locations. `src/os/windows/worker.rs:69`, `src/os/windows/worker.rs:154`. [OS reference 1](https://learn.microsoft.com/en-us/windows/win32/procthread/inheritance)

### AUD-001-API001 — MemoryLocked loses a successful process lock on re-entry

On a host where mlockall succeeds but the fork-wiped status marker cannot be created, a later default call reports NotRequested for the still-effective lock. The initialization caches a failed marker allocation or advice. The current kernel exercises the supported-marker path. Record an indeterminate state or implement a fork-safe readback fallback. This is a false negative and can block strict work. This is possible on Linux 4.4–4.13, or when the marker mapping/advice is refused independently of mlockall.

Frozen locations. `src/os/linux.rs:341`, `src/os/linux.rs:359`, `src/os/linux.rs:378`. [OS reference 1](https://man7.org/linux/man-pages/man2/madvise.2.html) [OS reference 2](https://man7.org/linux/man-pages/man2/mlock.2.html)

### AUD-003-SEC003 — Signal-filter ownership is recorded before installation succeeds

A refused installation now leaves the signal owner unchanged and the single-threaded failure regression passed. The owner PID is still shared across a process while a successful policy update applies to the calling thread. Sibling threads can retain different inherited rules and read the same affirmative owner. Strict mode can consequently confirm the wrong effective target. Track ownership with the actual per-thread filter and account for descendants.

Frozen locations. `src/os/linux/seccomp.rs:160`, `src/os/linux/seccomp.rs:329`, `src/os/linux/seccomp.rs:352`, `src/os/linux.rs:248`. [OS reference 1](https://man7.org/linux/man-pages/man2/seccomp.2.html)

### AUD-004-SEC001 — Default DLL search policy is presented as a universal allow-list

The rename and explicit-path exception narrow the claim. The public field still promises that every unqualified name uses only two directories. Windows can override default directories with per-call search flags even for a bare name. The technical overview still describes a universal restriction. State the default-search guarantee and avoid treating it as a strict allow-list.

Frozen locations. `src/protect.rs:286`, `src/os/windows.rs:346`, `src/os/windows.rs:453`, `docs/TECHNICAL.md:86`. [OS reference 1](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-setdefaultdlldirectories)

### AUD-006-FUN001 — Worker::end runs the teardown sequence twice

end computes the result of finish and then Rust drops the consumed Worker. Drop calls finish again. When the first wait fails, a second grace period can run, and its result is discarded. The return value can say the child is still alive after the second attempt reaped it. Shutdown can also take an additional grace period. The Linux test permits a 2.5-second window for a one-second refusal.

Make finalization one-shot. Preserve or explicitly transfer the ability to reap a child that outlives a refused termination. Cover one finalization attempt on refusal and a child that exits between the two deadlines. Check the returned status and wait count.

Evidence at f3c2401. `src/worker.rs:149`, `src/worker.rs:188`, `src/os/unix.rs:252`, `src/os/windows/worker.rs:53`, `tests/worker.rs:470`. [Reference 1](https://doc.rust-lang.org/std/process/struct.Child.html)

### AUD-006-SEC001 — Safe Unix worker bootstrap can close descriptors still owned by application code

serve trusts an environment marker to enter worker mode. Unix cleanup closes descriptors above stderr without checking who owns them. A later or repeated call in a host with live File or OwnedFd values can invalidate them. First entry in a fresh, single-threaded worker is the intended case. Previously opened files or pipes can become unusable. If a descriptor number is reused, a stale owner can act on or close another resource. The current first-call documentation alone cannot express this invariant of a safe function.

Move cleanup to a controlled pre-application launch phase. Make bootstrap single-use and ensure that only genuinely inherited descriptors are closed. Any externally assumed ownership invariant needs an appropriate API boundary. Exercise bootstrap with existing application-owned resources using a harmless ownership model. Verify normal fresh startup, refusal of repeat entry, and that the live owner retains its original resource.

Evidence at f3c2401. `src/worker.rs:205`, `src/worker.rs:214`, `src/os/unix.rs:296`. [Reference 1](https://doc.rust-lang.org/std/io/index.html#io-safety)

### AUD-006-FUN002 — The allocation gate ignores failure to block signals

The result of pthread_sigmask is ignored. Under a host policy refusing the operation, the code enters the gate anyway. If the same thread is interrupted by a handler that forks, the fork prepare handler can wait on that very thread. In this conditional Unix integration the process can hang despite the allocation-side timeout. No disclosure was established.

Check mask establishment before acquiring the gate and fall back to anonymous pages on refusal. Define how to handle failure to restore the previous mask. Test the refused-mask decision with a substitute OS-call result. Confirm the secretmem branch cannot be entered without an established mask.

Evidence at f3c2401. `src/os/linux.rs:116`, `src/os/linux.rs:153`, `src/os/linux.rs:184`. [Reference 1](https://man7.org/linux/man-pages/man3/pthread_sigmask.3.html)

### AUD-006-DOC001 — The terminal worker API claims it disables echo

start_on_terminal preserves stderr and the controlling terminal. It contains no password reader or termios change. The public text says that it turns echo off. The implementation can also inherit redirected stderr. An application using an ordinary terminal read in reliance on this promise may echo a password. The library itself does not read or display one during startup.

Describe echo setup, verification and restoration as responsibilities of the application reader. Update the wording or introduce an explicit reader with its own guarantee. Review the public example with a TTY and redirected stderr, using public text. If a hidden reader is later introduced, check the actual terminal state before and after input.

Evidence at f3c2401. `src/worker.rs:60`, `src/os/unix.rs:215`, `src/worker.rs:218`, `docs/TECHNICAL.md:168`.

### AUD-006-DOC002 — The Linux file-change outcome differs from the documented external-denial case

The guide groups NoFileChanges with NoNewSockets and says an external denial without the crate filter yields Unknown. NoFileChanges instead returns Refused whenever the filter is absent and does not probe on that path. Strict callers reject both, but diagnostics can incorrectly tell users what was established about their environment.

Specify the intended file-change status separately or implement the documented proof distinction. Assert the selected outcome without a local filter and compare the public descriptions with the returned status.

Evidence at f3c2401. `src/os/linux.rs:272`, `docs/TECHNICAL.md:113`.

### AUD-006-BLD001 — A failed grandchild creation or wait can pass the same-PID regression

Inside the nested-namespace branch the test initializes status to zero and does not check for a failed fork or the return of waitpid before using status. A failure can therefore be reported as a successful child result. The green top-level check is weaker evidence of the same-PID subcase than its name suggests. This affects the test, not the fork-wiped marker implementation.

Require a positive child PID and successful waiting for that exact PID before evaluating its termination. Report unavailable prerequisites explicitly. Verify the successful path and deliberate harness-side launch/wait refusal. An uncollected result must not count as a passed assertion.

Evidence at f3c2401. `tests/isolation/linux/roles.rs:149`, `tests/isolation/linux/roles.rs:155`.

## Integration and limits

Secret::with_capacity and Secret::zeroed use best-effort page locking when kernel secret memory is unavailable. For a buffer that must remain out of swap, use Secret::locked and check its Result before filling it. Internal worker request and response allocation uses Secret::zeroed. Choosing a strict constructor only for a caller-owned buffer does not enforce a lock for those IPC allocations.

The Windows child-policy exception and both active-process/UI job limits have source changes. A pre-existing job can have breakaway settings. Its one-member limit is a claim about processes associated with the job and does not on its own prove universal child-process prevention.

Snapshot-specific line references can be inspected with git show f3c2401:<path>. The post-build working-tree edits and any later commits need their own verification.

Native Linux x86-64 on kernel 7.0.0-43-generic and a linked wasm32-unknown-unknown module in Node/V8 were executed. Clippy checked six triples. macOS, iOS, Windows, Android and an old-glibc runtime did not execute. A Linux build of Windows source cannot verify AppContainer, job or inheritance behavior.

The measured LLVM percentage excludes non-Linux code and worker-side paths that cannot emit profiles after the deliberate environment reset. Four lock-dependent cases were excluded under ASan. Leak checking is disabled in the test binaries. Coverage is evidence of execution, not a security guarantee.

The 31 mutation reversions and the reported seven historical disclosures in 400 trials were not independently replayed. The repository was frozen and the audit did not modify any production code. No secret data was used.

Boundary cases in findings are reported from source, contract checks and public documented OS semantics. No end-to-end secret disclosure, pentest, leak-freedom proof or native foreign security certification is claimed.

Current advisory results are bound to the local database. No new dependency internals, consumer GUI, package deployment, hibernation, VM snapshots, or privileged operating-system access were audited.
