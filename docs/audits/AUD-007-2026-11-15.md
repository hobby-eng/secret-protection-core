### Previously open finding that remains open

#### AUD-001-SEC004 — High — Windows worker pipe ends remain briefly inheritable

- **Status:** Open at `f3c2401`; no duplicate finding assigned.
- **Affected code:** `src/os/windows/worker.rs:114-184` and `src/os/windows/worker.rs:271-325`.
- **Expected:** Only the designated worker and its parent can possess the secret IPC endpoints.
- **Observed:** Pipes begin non-inheritable, but the two child ends are made inheritable around `CreateProcessW`. `LAUNCHING` serializes this crate's launches only; another part of the program using broad handle inheritance can receive them in that window. The limitation is explicit in `docs/TECHNICAL.md:166` and `docs/TECHNICAL.md:219`.
- **Impact:** On a Windows host with such a concurrent launcher, an unintended child can own a secret request/response channel. No Windows runtime observation was available.
- **Evidence:** Static source and documentation review. The subsequent uncommitted Windows-worker change is outside this snapshot and was not assessed.
- **Required resolution:** Use a launch design that never makes the endpoints inheritable and verify concurrent independent launches on Windows.
