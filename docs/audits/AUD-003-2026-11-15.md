### AUD-003-SEC001 — A selective host policy can satisfy strict socket checks

Linux and Android can confirm NoNewSockets from a denied socket probe even when the library filter was refused. A policy that restricts only the probed operations can therefore satisfy the strict check while permitting other sockets. The analogous optional flock and sendmsg checks inspect a single operation without establishing their option bits.

A worker can admit a secret under an unestablished socket boundary. Require positive evidence of the installed filter and relevant option bits together with the existing checks. Report an indeterminate outcome when only an external denial is visible.

Cover a partial external policy and absent local policy with a controlled policy-result fixture. Strict startup must decline those requirements.

### AUD-003-SEC002 — A tracer can be invisible to the procfs PID namespace

The improved check enumerates threads. Linux projects each tracer PID into the namespace used by procfs. An already attached tracer outside that namespace can be rendered as zero. A confirmed NoMemoryReading therefore overstates the visible evidence for such a deployment. The threat model excludes privileged readers but the published outcome expressly claims to identify a pre-attached debugger.

A caller can rely on a misleading strict memory-reading status in a PID namespace. Define the visibility assumption in the API and carry an indeterminate result into strict mode when it cannot be established.

Check the interpretation across PID namespace boundaries, and retain the ordinary same-namespace regression.

### AUD-003-SEC003 — Signal-filter ownership is recorded before installation succeeds

The shared PID records construction of a candidate filter. A rejected update can leave the inherited older filter in effect while reporting its signal rule as belonging to the current process. The thread on which the rule actually applies matters too.

A strict caller can accept a rule that still names the wrong process. Update provenance only after confirmed installation and associate it with the effective filter and thread. Treat inherited, unverifiable provenance conservatively.

Exercise an inherited rule and unsuccessful policy update through a state-machine test. Check the reported PID ownership after failure.

### AUD-003-FUN001 — Worker teardown can wait indefinitely after termination is requested

On Unix a failed kill is followed by a blocking wait, including when the parent itself no longer has the right to signal its child. Windows ignores the termination result and follows it with INFINITE. An error in call closes the pipes. The one-second grace begins in finish, which can be postponed while the broken Worker remains alive.

A caller waiting for disposal can remain blocked while the child is still alive. Handle termination errors explicitly and bound both waiting phases. Specify the lifetime after a failed request, with a reaping or supervision policy when the caller cannot terminate the child.

Test refusal through a termination abstraction and check an explicit shutdown result and time bound. Retain both the cooperative oversized-reply check and the ordinary lingering-child check.

### AUD-003-API001 — A previously refused Landlock layer is not retried on identical entry

When seccomp is already installed with the requested options, restrict returns before checking whether the Landlock layer succeeded. The documented retry promise does not hold for an initially refused layer followed by the same options.

The missing layer can persist after a transient refusal even when the caller retries. Track the layer independently when deciding whether to retry. If sandboxing has made a retry impossible, describe and report that state.

Use a state transition test from rejected layer plus installed filter to the next identical request.

## Interpretation

The handshake correctly delays the first request until the clean flag, decoded report and required outcomes are accepted. Some individual outcomes can still overstate what the operating system enforced. The report is supplied by the same trusted executable, with no independent proof of its identity. Deployment should retain that assumption when resolving current_exe by path.

The one-second grace concerns teardown. Reading the initial report and completing normal request I/O use synchronous reads with no deadline. A host that needs a response deadline must account for that separately.

On the supported Linux/Android filter backends pidfd_send_signal is explicitly denied for any destination when the self-only option is installed. This is an option-specific rule.
