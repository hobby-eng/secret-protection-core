## Findings

### AUD-001-SEC001 — High — Linux secret-memory allocation and concurrent fork share an inheritance window

During successful secretmem allocation, the shared backing file is temporarily open across fork. DONTFORK affects a mapping and CLOEXEC takes effect at exec. Neither revokes an already inherited descriptor. A concurrent fork without immediate exec can retain the same backing object into which the parent later places secret bytes. The private anonymous fallback has different sharing semantics. The diagnostic confirmed use of secretmem on the host, without testing disclosure.

Expected behavior. Child exclusion must hold for a buffer reported out of children.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. The native public diagnostic identified the active backend only. No secret transfer was tested. [src/os/linux.rs line 44](../../src/os/linux.rs#L44) · [src/os/linux.rs line 57](../../src/os/linux.rs#L57) · [src/os/linux.rs line 74](../../src/os/linux.rs#L74) · [src/os/unix.rs line 33](../../src/os/unix.rs#L33) · [OS or language contract](https://man7.org/linux/man-pages/man2/memfd_secret.2.html) · [OS or language contract](https://man7.org/linux/man-pages/man2/mlock.2.html)

Recommended change. Use the private anonymous backend when fork can run concurrently. Reserve shared secretmem for a fork-free worker or a caller with an enforceable fork-free lifecycle. Make this precondition part of the guarantee.

Required verification. Check both backends, allocation lifecycle and process model using public fixtures on supported Linux kernels. Verify the claimed scope before accepting sensitive input.

### AUD-001-SEC002 — High — Unix worker acknowledges isolation after incomplete descriptor cleanup

After the bulk close fails or is unavailable, directory-open failure silently returns, directory-entry errors are discarded and close results are ignored. Startup still sends the protection bits. If the worker inherited a writable file or socket and fallback enumeration fails, the strict handshake can accept secrets with the channel still present. The normal Linux close_range path is unaffected.

Expected behavior. A worker advertising clean inherited channels must know that all unintended descriptors were closed.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/os/unix.rs line 252](../../src/os/unix.rs#L252) · [src/os/unix.rs line 264](../../src/os/unix.rs#L264) · [src/os/unix.rs line 274](../../src/os/unix.rs#L274) · [src/worker.rs line 150](../../src/worker.rs#L150)

Recommended change. Propagate the cleanup outcome before sending the handshake. Use a supported close-from operation or a verified fallback, with explicit handling of the listing descriptor and OS close semantics.

Required verification. Verify clean startup and startup refusal on incomplete cleanup with public descriptors, including the fallback on macOS.

### AUD-001-SEC003 — High — Linux tracer evidence for one thread is reported process-wide

TracerPid is read only for the calling thread. Setting the process non-dumpable restricts new access and does not detach existing tracers. Linux ptrace attaches per thread. A multithreaded caller can pass a required NoMemoryReading check despite an existing tracer of a different thread sharing its memory. The single-threaded worker avoids this particular mismatch.

Expected behavior. A positive process-wide result requires evidence covering prior tracers on all relevant threads.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/os/linux.rs line 140](../../src/os/linux.rs#L140) · [src/os/linux.rs line 282](../../src/os/linux.rs#L282) · [src/os/linux.rs line 775](../../src/os/linux.rs#L775) · [src/protect.rs line 241](../../src/protect.rs#L241) · [OS or language contract](https://man7.org/linux/man-pages/man2/ptrace.2.html)

Recommended change. Establish the property before concurrency, or implement a sound process-wide check under a controlled thread lifecycle. Otherwise mark it unverified for a multithreaded caller.

Required verification. Cover single-thread initialization, multithread scope and unavailable thread inventory. A process-wide positive result must refer to the entire claimed scope.

### AUD-001-SEC004 — High — Windows worker pipe ends are briefly inheritable by unrelated launches

Both ends are created inheritable. Inheritance is cleared later on the parent ends. The explicit handle list limits inheritance for the worker launch only. A separate child spawned concurrently by the same parent using broad handle inheritance can receive an IPC endpoint. This applies to applications with such process-launch behavior. No Windows runtime observation.

Expected behavior. Only the designated worker and its parent may hold secret request and response pipe handles.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/os/windows.rs line 855](../../src/os/windows.rs#L855) · [src/os/windows.rs line 919](../../src/os/windows.rs#L919) · [src/os/windows.rs line 962](../../src/os/windows.rs#L962) · [src/os/windows.rs line 987](../../src/os/windows.rs#L987) · [OS or language contract](https://learn.microsoft.com/en-us/windows/win32/procthread/inheritance)

Recommended change. Keep inheritable ends in a dedicated launch broker with controlled child creation, or enforce coordinated allowlisted inheritance across all launchers in the process. Creating parent ends non-inheritable also narrows the window.

Required verification. Validate handle ownership during concurrent independent benign launches on Windows. Verify only designated actors can own the IPC endpoints.

### AUD-001-SEC005 — High — macOS accepts local probe denials without a confirmed sandbox profile

The result of sandbox_init is used only to free an error message. A permission denial creating one temporary file can come from its directory. A single UDP loopback check likewise cannot characterize an unknown profile. When profile installation fails, an ordinary pre-existing directory restriction can satisfy NoFileChanges while other directories remain writable. A caller requiring the flag can then admit secret input.

Expected behavior. A strict, process-wide file or network restriction requires confirmation of the intended profile or independently equivalent policy.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/os/apple.rs line 103](../../src/os/apple.rs#L103) · [src/os/apple.rs line 108](../../src/os/apple.rs#L108) · [src/os/apple.rs line 127](../../src/os/apple.rs#L127)

Recommended change. Track actual successful profile installation, including re-entry, and combine it with the intended readbacks. Return unknown on an unverified external sandbox.

Required verification. On macOS verify first success, repeat entry, and refused installation with independently restricted probe locations in disposable processes.

### AUD-001-SEC006 — Medium — Signal-domain isolation can satisfy a stricter self-only claim

A successful seccomp installation plus Landlock ABI support can stand in for a failed Landlock application. An enforced Landlock signal scope groups processes. The self-only filter separately embeds the installing process ID, which is inherited across fork. A required ForeignSignalsRefused result can mean separate things and can be positive without the advertised restriction. A child cannot interpret an inherited fixed-ID filter as its own self-only policy.

Expected behavior. Evidence must distinguish self-only addressing, a Landlock domain boundary and unsupported enforcement.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/os/linux.rs line 150](../../src/os/linux.rs#L150) · [src/os/linux.rs line 170](../../src/os/linux.rs#L170) · [src/os/linux.rs line 223](../../src/os/linux.rs#L223) · [src/os/linux.rs line 624](../../src/os/linux.rs#L624) · [src/protect.rs line 272](../../src/protect.rs#L272) · [OS or language contract](https://docs.kernel.org/userspace-api/landlock.html)

Recommended change. Distinguish confirmed signal-domain scope from self-only mode, track enforcement separately from availability, and bind or restrict the supported process lifecycle.

Required verification. Test each enforcement state independently, including unavailable Landlock, repeated entry and supported descendant semantics. Verify the strict requirement accepts only the requested property.

### AUD-001-SEC007 — Medium — Unsupported speculation control is accepted as confirmed mitigation

For indirect branches the implementation accepts ENODEV. The kernel defines it as an unsupported selector, while a successful zero return identifies an unaffected CPU. The code also groups ordinary disable with irreversible disable. The strict requirement or detailed report can overstate speculative-execution mitigation on particular architectures and configurations. No leakage was observed.

Expected behavior. A positive mitigation claim needs a confirmed protection or a supported indication that the CPU is unaffected.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/os/linux.rs line 259](../../src/os/linux.rs#L259) · [src/os/linux.rs line 272](../../src/os/linux.rs#L272) · [src/protect.rs line 257](../../src/protect.rs#L257) · [OS or language contract](https://docs.kernel.org/userspace-api/spec_ctrl.html)

Recommended change. Represent unsupported as unknown and distinguish reversible from permanent disable where the public contract promises permanence. Permit platform-specific equivalents only with evidence.

Required verification. Validate the mapping from independent kernel results to supported, unaffected, reversible, irreversible and unknown statuses.

### AUD-001-SEC008 — Medium — Protected stack properties cannot be required before secret work

Page advice and locking are best effort. Apple explicitly reports no per-mapping dump exclusion. The callback runs before the caller receives even the lock result. Dump and child flags are omitted from StackRun. A standalone caller on Apple, or a caller under Linux policy or quota restrictions, can put secret temporaries on a stack that falls short of the documented protection.

Expected behavior. A caller relying on exclusion or locking must verify those properties before invoking its callback.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/stack.rs line 12](../../src/stack.rs#L12) · [src/os/unix.rs line 170](../../src/os/unix.rs#L170) · [src/os/unix.rs line 184](../../src/os/unix.rs#L184) · [src/os/unix.rs line 358](../../src/os/unix.rs#L358) · [src/os/unix.rs line 391](../../src/os/unix.rs#L391)

Recommended change. Provide a pre-callback required-properties policy and report the mapping outcomes. Identify when a separately confirmed process-wide measure supplies an equivalent guarantee.

Required verification. On Linux and Apple assert that missing required flags prevent callback entry. Test the best-effort API and normal/panic completion separately.

### AUD-001-SEC009 — Medium — Stack wiping assumes every post-pthread byte is an initialized Rust u8

The code forms a mutable slice of initialized bytes over an entire used stack. Arbitrary frames can contain uninitialized storage or padding even though the original mapping was zero-filled. pthread_join's return value is discarded. The unsafe conversion lacks an initialization proof for a safe public API. Successful ordinary tests do not establish this invariant. No optimizer-induced leak was observed.

Expected behavior. Final wiping must be valid for arbitrary used stack memory and may begin only once all thread access has ended.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/os/unix.rs line 379](../../src/os/unix.rs#L379) · [src/os/unix.rs line 386](../../src/os/unix.rs#L386) · [src/os.rs line 105](../../src/os.rs#L105) · [OS or language contract](https://doc.rust-lang.org/std/slice/fn.from_raw_parts_mut.html)

Recommended change. Use a write-only raw wipe or a MaybeUninit byte representation with an optimization-resistant wipe. Establish successful join before releasing the backing allocation and job.

Required verification. Review lifetime and initialization invariants, check generated wipe code, and exercise normal and panic paths on supported Unix runtimes.

### AUD-001-SEC010 — Medium — ClosedSecret forgets the previous access mode after a refused reseal

A read-only opening followed by refused resealing leaves the closed boolean false. A subsequent refused read-write transition can therefore be ignored even if the mapping is still read-only. When OS policy refuses both transitions, a write or cleanup can fault. The condition does not establish disclosure and was not observed on this host.

Expected behavior. A mutable reference or destructor wipe requires confirmed write access, including after OS protection failures.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/protect/closed.rs line 112](../../src/protect/closed.rs#L112) · [src/protect/closed.rs line 135](../../src/protect/closed.rs#L135) · [src/protect/closed.rs line 144](../../src/protect/closed.rs#L144)

Recommended change. Track actual access permissions explicitly and distinguish unsupported backends. Refuse any operation whose required access cannot be established before producing the reference or wiping.

Required verification. Exercise policy-refused transitions from read-only state, including drop and callback unwinding, with public data.

### AUD-001-SEC011 — Medium — Windows dynamic-code status ignores permitted exemptions

Readback tests ProhibitDynamicCode alone. A policy may also set AllowThreadOptOut or AllowRemoteDowngrade. A strict requirement can accept a preconfigured and weaker dynamic-code policy. The scope is installations carrying those mitigation settings.

Expected behavior. A process-wide permanent prohibition must account for Windows policy exceptions.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/os/windows.rs line 327](../../src/os/windows.rs#L327) · [src/os/windows.rs line 334](../../src/os/windows.rs#L334) · [src/os/windows.rs line 389](../../src/os/windows.rs#L389) · [OS or language contract](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-process_mitigation_dynamic_code_policy)

Required verification. Validate the official policy combinations on supported Windows versions and expose partial coverage explicitly.

### AUD-001-FUN001 — Medium — Dropping a worker can wait forever after rejecting a large reply

The parent rejects the advertised size, retains the unread output pipe, closes only the input and waits. The child can be blocked writing the rest of a legitimate answer. When the remaining reply exceeds pipe capacity, both sides can wait indefinitely. The standard test uses a 100-byte reply that fits in the pipe.

Expected behavior. A rejected, oversized answer should permit prompt disposal and reaping of the worker.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/worker.rs line 112](../../src/worker.rs#L112) · [src/worker.rs line 125](../../src/worker.rs#L125) · [src/worker.rs line 173](../../src/worker.rs#L173) · [src/os/unix.rs line 243](../../src/os/unix.rs#L243) · [src/os/windows.rs line 785](../../src/os/windows.rs#L785) · [OS or language contract](https://man7.org/linux/man-pages/man7/pipe.7.html)

Recommended change. Close both IPC directions before waiting. Define a bounded shutdown policy for broken workers and mark partial transport failures terminal.

Required verification. Use a normal large public response with a bounded test deadline on Unix and Windows. Verify prompt return and child reaping.

### AUD-001-FUN002 — Medium — Fork-based work inside a protected stack may lose its active stack

The active stack is configured to be wiped or excluded on fork. A non-terminal Unix Worker start registers a pre_exec closure, where the child needs usable execution state before exec. A caller that starts a fork-based operation from the protected stack can lose its active return frames in the child. Normal stack-only tests do not exercise this composition.

Expected behavior. The callback contract should identify supported ways to launch children safely.

Verification basis. Static control-flow and contract review of the cited lines at the reviewed commit. [src/os/unix.rs line 170](../../src/os/unix.rs#L170) · [src/os/unix.rs line 183](../../src/os/unix.rs#L183) · [src/os/unix.rs line 220](../../src/os/unix.rs#L220) · [src/os/unix.rs line 358](../../src/os/unix.rs#L358)

Recommended change. Document and enforce the relevant process lifecycle where feasible. Start workers outside this stack or use a launch design independent of its post-fork frames.

Required verification. Check supported process-launch combinations with plain public operations on Linux and Apple and document any unsupported ones.

### AUD-001-API001 — Medium — MemoryLocked loses a successful process lock on re-entry

## Remediation and follow-up

All findings are open against the reviewed commit. No fixes or fix-verification commits were made. A blocker in the register applies to integrations relying on the affected guarantee. Address the five high-severity boundary failures first. Verify required flags, stack entry and unsafe cleanup before enabling their strict profiles.

## Integration guidance

- Use a fresh single-threaded, fork-free worker where the platform supports one. Verify required protections and intended channel ownership before admitting test or user secrets. Mobile integrations need their own platform-specific isolation and device evidence.
- Protect long-lived secrets and Argon2 work areas explicitly. Determine whether a given allocation fits the lock quota. A strict configuration that requires locked work memory must refuse the sensitive operation when it cannot obtain it. Keep whole-process locking opt-in.
- The current worker protocol accepts a u32 byte count and makes a non-fallible allocation on the receiving side. Define application-specific request/reply maxima, use fallible allocation for untrusted sizes, and retire broken transports on partial I/O.
- Measure names should distinguish socket creation, usable network connections, and inherited channels. A token capability check is evidence about policy, not an observed network connection test.
- Forked descendants should not reuse copied protected-buffer objects or cached lock flags. Memory locks are not inherited and mappings can be wiped or absent.
- Verify the integration against native OS crash handling. Windows reports no whole-process NoCoreDumps and Windows Error Reporting can retain stacks and registers. WASM offers buffer wiping only. SIGKILL and abort do not execute Rust Drop. Hibernation and VM snapshots require OS policy.

## Limitations

- Native runtime evidence is limited to Linux x86_64 on kernel 7.0.0-43-generic. Clippy type-checked other targets. No native Windows, macOS, iOS, Android or WASM runtime, installer, link test or end-to-end consuming application was exercised.
- The ordinary suite, diagnostic and code review do not certify complete memory erasure, impossibility of disclosure, or resistance to privileged OS access. No secret transfer or exploit was demonstrated. No formal proof, sanitizer or disassembly campaign was performed.
- The host used a fresh target directory and offline locked dependencies. Upstream dependency internals and current transitive advisories were not audited.
- The library tests did not cover terminal password entry in a consuming application, integration with a steganography application, browser interfaces, suspend images, VM snapshots or device-wide crash collectors.
