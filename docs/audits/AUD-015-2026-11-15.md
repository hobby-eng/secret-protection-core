## Results

- Linux x86-64 passed 84 checks in debug and release (33 unit · 20 isolation · 9 secret-memory · 22 worker). Coverage measured 2,468 of 2,596 lines (95.07%). [Scope and per-file counts](../COVERAGE.md)
- One additional release run timed out in the fork test. During that run the resource wrapper suspended its process group for over two minutes and the test had a one-minute wall-clock watchdog. The full suite passed again with the workspace wrapper’s standard thresholds. Both runs are retained.
- Rustfmt passed in both workspaces. Clippy passed with warnings denied on all six configured targets and for the fuzz bins. RustSec checked the root and fuzz lockfiles. The four Windows test programs were cross-linked.
- AddressSanitizer passed 80 checks with four locking-related exclusions. Miri passed the uninitialized-memory wipe test. The release harness checked 1,112,064 Unicode scalars, seven invalid frames and the capacity boundary. V8 passed four WASM fallback checks.
- All three sanitizer-backed fuzz targets completed their 90-second budgets. Runs completed were 9,771,028 for setting, 21,787,658 for report and 299,409 for keystrokes. The interrupted keystrokes run is excluded. Isolated reruns of retained slow inputs are in the command record.
- The additional launch of the foreign-filter test inside a user/PID namespace passed. The separate integration check for memory ownership across two PID namespaces reported `test a PID namespace of its own leaves the reading of memory unknown ... ok`.
- Independent static review covered the Unix and Windows changes and completeness against the earlier audits. The private descriptor table, first-reply memory eligibility, whole-process admission and Windows access mask each have a regression test. The Linux threaded-worker regression uses the real launcher, including when instrumented for coverage.

The JSON record links every CORE and audit checklist item marked failed in AUD-014 to its follow-up. The operating-system and runtime limits in the release conditions apply to those results as well.

## Release conditions

On Windows require the ordinary worker to start, the isolation report to refuse a strict LowIntegrity requirement while a sibling impersonates a higher-integrity token, and the retained handle to grant exactly the two lifecycle rights. On macOS require cooperative shutdown and a false result for a worker kept alive past its grace period. Run Linux AArch64 CI on the same revision before tagging. The earlier green CI builds refer to older bytes.
