### Findings

#### AUD-013-SEC001 — Medium — Worker startup closes a descriptor number a linked library has reused

- **Category:** SEC.
- **Severity:** medium.
- **Status:** open.
- **Release blocking:** true. A release that repeats the current startup sentence would state a boundary the code does not keep. No inherited file was shown to remain open.
- **Affected files and builds:** `src/os/unix.rs` (`before_main`), `src/worker.rs` (`inherited`, `starts_clean` caller), `docs/TECHNICAL.md`, `CHANGELOG.md`. Linux, Android and macOS worker startup. The probe ran on Linux x86-64.
- **Reproduction:** Link a shared library whose constructor closes an inherited descriptor above standard error and opens `/dev/null`, receiving the same number. Start that executable with `SECRET_PROTECTION_CORE_WORKER` set to `0,0,<that number>`, as `Worker::start` does. The untracked probe under `docs/audits/AUD-012-harnesses/` does this with `/dev/null` only.
- **Expected behavior:** `docs/TECHNICAL.md` says the pre-`main` function closes the numbers the parent named and no other, and that a descriptor a library opened before that function ran stays the library's. `CHANGELOG.md` says the same. The comment on `before_main` says the number is one no program code can hold while it is open.
- **Observed behavior:** The probe exited 1 with `FAIL: worker startup closed the linked library's reused descriptor`. Shared-library constructors run before the executable's `.init_array`, so the library's `open` reuses the number, and `before_main` then closes that number. `starts_clean` only asks whether any descriptor above 3 remains. After this close, that check can pass.
- **Impact:** A library constructor that closes a stray descriptor and opens its own file can lose that file. The parent can still treat the start as clean and send a request. The inherited file itself was already closed by the library, so this probe does not show that file surviving. Replacing standard input or output was not executed.
- **Evidence:** Probe exit 1. `src/os/unix.rs` closes every number from `inherited` with `libc::close` and does not compare device and inode. `starts_clean` accepts a listing whose numbers are all at most 3, plus a closed descriptor 3.
- **Recommended fix:** In the parent, record the device and inode of each inherited descriptor. In `before_main`, close a number only when it still names that file. If the number was reused, leave it and let `starts_clean` refuse the start. Narrow `docs/TECHNICAL.md` and `CHANGELOG.md` to the behavior the code actually keeps until that check exists.
- **Required verification:** The reuse probe must exit 0, and a descriptor that still names the parent's file must still be closed. `cargo test --test worker` on Linux and macOS.

#### AUD-013-API001 — Low — `ClosedSecret::is_closed` ignores fork generation

- **Category:** API.
- **Severity:** low.
- **Status:** open.
- **Release blocking:** false. Reads and writes in the child still abort through `Pages::check`.
- **Affected files and builds:** `src/protect/closed.rs`, Unix.
- **Reproduction:** Build a `ClosedSecret`, `fork`, and in the continuing child compare `is_closed` with `is_locked` and `is_out_of_children`.
- **Expected behavior:** `is_locked`, `is_out_of_dumps` and `is_out_of_children` are false when `Pages::here` is false. `is_closed` should not report closed pages the child does not hold.
- **Observed behavior:** `is_closed` returns `self.access == Access::Nothing` and does not call `here`.
- **Impact:** Status lie in a child that continues after `fork`. No reference to the parent's pages is formed by the query.
- **Evidence:** `src/protect/closed.rs` lines 94–97 against `src/os.rs` `here` and `is_locked`.
- **Recommended fix:** Return `self.secret.pages.here() && self.access == Access::Nothing`. Extend the fork test to expect `!is_closed()` in the child.
- **Required verification:** `cargo test --test secret_memory` on Linux and macOS.
