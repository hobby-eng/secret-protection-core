# AUD-017 — Four reviews of the changes since 0.1.1 and their remediation

## Release decision

**Not ready for release until the native runs on Linux ARM64, macOS and Windows pass every [acceptance criterion](#acceptance-criteria).** Four reviews read everything added since 0.1.1 (the AUD-016 fixes, stack clearing, hidden terminal input, folders granted for writing with the strict channel check, and `Options::all_threads`) and then each round of its remediation. Together they found 2 High, 28 Medium and 36 Low findings, and review 1 made three observations. No Critical defect was found, and no review found a memory-safety defect in the `unsafe` and FFI code.

The base is commit `a0fad153b3e361ca58e6256ac6746e65331588a1` on `feature/all-threads`, above `v0.1.1`. The fixes are in `3ae1764` (reviews 1 to 3) and the follow-up rounds `e0809b2`, `306996f`, `2807c51` and `f3da0e2`; the version is 0.2.0. Each finding below says where it was fixed and whether review 4 verified the fix or a native run still has to.

### AUD-017-SEC001 — High — Linux TSYNC propagates folder permissions without their Landlock boundary

Reviews 1, 2 (GEM-SEC001). With `Options::all_threads` the seccomp filter went onto every thread with TSYNC while the Landlock layer went there only from ABI 8, or not at all after folders had been granted. The filter's marks `LAYER`, `SCOPE` and `FOLDERS` then reached threads without the layer: such a thread could create, rename and remove files wherever the folder rules allow, and a later `Isolation::enter` on it read the marks and reported `NoFileChanges` and `SignalsWithinLayer` as Confirmed.

Fix in `3ae1764`. The filter goes onto other threads only where the layer did, by this call's TSYNC or as recorded for the process, or where the calling thread holds no layer at all. Below ABI 8 both stay on the calling thread and report `Reach::Thread`. Tests: the thread roles on every ABI, and `sibling-then-folders` (folders granted beside a running thread, then `all_threads`: the other thread keeps its sockets). Review 4 verified it at `3ae1764`.

### AUD-017-SEC014 — High — Concurrent Linux isolation calls race

Review 2 (GEM-SEC002). Both read no layer and no filter; one call's empty layer, put on every thread, closed the folders the other granted while it reported `FolderWrites` Confirmed. A false report, and folders closed under a program that was told they are open.

Fix in `3ae1764`. Linux isolation calls run one at a time (`Entering`), a flag that carries the process's mark, its number and fork count, so a child of `fork` made while another thread held it takes it over. Review 4 verified it at `3ae1764`.

### AUD-017-SEC002 — Medium — Landlock TSYNC can replace a sibling's protection before seccomp refuses synchronization

Review 1. The layer's TSYNC replaced the Landlock domain of every other thread before the filter's TSYNC ran, and the kernel refuses the filter's TSYNC when a thread holds a filter the caller's does not descend from; that thread was left with the caller's layer and its own filter.

Fix in `306996f`. Before the layer's TSYNC a filter that allows everything goes onto every thread with TSYNC (`seccomp::share_filters`), which the kernel refuses, putting it nowhere, in just that case; the whole call then stays on the calling thread. The layer's TSYNC is tried once per process, right after that check (follow-ups SEC027, SEC031). A call that falls short later leaves other threads more restricted, never less, as the guides say; the option's precondition, no Landlock layer of their own on other threads, is written in the rustdoc and the guides. Test: `foreign-sibling`. Review 4 verified it at `306996f`.

### AUD-017-SEC003 — Medium — Linux thread census can certify whole-process reach with a surviving sibling

Review 1. `one_thread` counted the entries of `/proc/self/task`, which can skip a thread that exits next to a live one, so a process of two threads could read as one; `traced` trusted the same listing.

Fix in `3ae1764`. The count of threads is the kernel's own, the `Threads:` line of `/proc/self/status`. `traced` counts only the statuses it read and requires that number to equal the count before and after its walk, else walks again, up to three times, then reports unknown (follow-up SEC018). An atomic view of the threads does not exist, so heavy churn can still make it unknown. Its verification waits for a native run or a later review.

### AUD-017-SEC004 — Medium — macOS channel checks miss some writable shared file mappings

Reviews 1, 2 (GEM-SEC005). The macOS region walk counted a region as shared by its share mode or `VM_INHERIT_SHARE`; XNU reports a file mapped shared by one process as `SM_PRIVATE`, and `minherit` changes the inheritance, so a writable `MAP_SHARED` file mapping whose descriptor was closed could pass `OpenChannels::only`. `proc_regionfilename` could also name another region's file.

Fix in `3ae1764`. The walk uses `PROC_PIDREGIONPATHINFO`, which returns each region with the file it maps. A writable region that maps a file counts unless it is copy-on-write or empty, whatever its inheritance; names come from the same call. Its verification waits for a native run or a later review.

### AUD-017-SEC005 — Medium — macOS folder privacy can ignore inherited ACL permissions

Reviews 1, 2 (GEM-SEC011). `is_private` read only the mode, while a new macOS folder inherits access-list entries that can grant other users access despite mode 0700.

Fix in `e0809b2`. On macOS `is_private` is false when an access list on the folder or above it allows anything to anyone or cannot be read, and when the volume is mounted to ignore owners (follow-up SEC029). Its verification waits for a native run or a later review.

### AUD-017-SEC006 — Medium — Windows reports successful hidden input after failed console discards

Reviews 1, 2 (GEM-SEC010). `FlushConsoleInputBuffer` ran before and after the reading unchecked; it needs write access, which a console input handle may lack, so typed-ahead input could join the line and the rest of a paste reach the next reader.

Fix in `3ae1764`. A failed first discard refuses the reading; the last runs only after a switch that read back, after the mode is restored, and fails the call; the restored mode is read back. Its verification waits for a native run or a later review.

### AUD-017-SEC007 — Medium — Unix hidden input does not verify or report an incomplete restore and drain

Reviews 1, 2 (GEM-SEC008, GEM-SEC009). The Unix restore set the settings without reading them back, drained under settings it had not verified to be non-blocking, and ignored a drain that failed or stopped at its cap; `terminal_for` took an `fcntl` failure for read-write, and two unknown devices compared equal.

Fix in `e0809b2`. The drain runs only under hidden settings with `VMIN` 0 that read back and must reach the end of the waiting input; the original settings, speeds included, are read back after the restore; each failure is an error, and the restore's error wins. `fcntl` failure refuses the descriptor, and an unknown device matches nothing. Review 4 verified it at `e0809b2`.

### AUD-017-SEC008 — Medium — Stack clearing does not run when the callback unwinds

Reviews 1, 2 (GEM-SEC003). `with_cleared_stack` cleared after a normal return only; WebAssembly has no guard page for a clearing deeper than its stack, and the 128 KiB array was written twice.

Fix in `3ae1764`. A guard clears when the frame is left, by return or unwinding; the work runs below a 2 KiB cushion of unwritten stack, so the clearing starts above its frames; zeros are written once, in place; WebAssembly clears nothing. Tests mark the work, the closure's own locals and a panicking work. Review 4 verified it at `3ae1764`.

### AUD-017-SEC009 — Medium — macOS folder grant is expressed by pathname after the identity check

Review 1. The macOS sandbox grants a folder by its path after the crate checked the folder's identity by descriptor; another user who can move the folder or a folder above it could put another at that path.

Fix in `e0809b2`. On macOS `is_private` is false when a folder above, up to the root, belongs to someone other than the user or root, lets its group or others write without the sticky bit, carries an access list that allows anything to anyone, or lies on a volume mounted to ignore owners. The grant stays by path, as the guides and `SECURITY.md` say; the example checks `is_private` before granting. Its verification waits for a native run or a later review.

### AUD-017-SEC013 — Medium — A synchronized Linux worker can pass clean startup with an unchecked descriptor table

Review 1. A worker checked the serving thread's descriptor table, while another thread started before `serve` could hold a table of its own that no census reads; with `all_threads` or a recorded filter such a worker was admitted.

Fix in `e0809b2`. A worker isolates itself without `all_threads` and, on Linux, is unclean unless it has one thread, by the kernel's count, checked before its descriptor census (follow-up SEC028). Review 4 verified it at `e0809b2`.

### AUD-017-SEC015 — Medium — A child of fork cannot signal itself under the inherited rule

Fix in `3ae1764`. The option's row says that the child cannot lift the inherited rule and what it can signal before and after isolating itself; the fork test asserts `EACCES`. Review 4 verified it at `3ae1764`.

### AUD-017-SEC016 — Medium — Windows integrity checks of threads with the hardened access list

Review 2 (GEM-SEC007). A thread opened after it got the hardened list may refuse the token query, reading Unknown; an ended thread's pinned handle stayed in the map. An honest Unknown where a Confirmed would hold; a handle kept until the call returned.

The access list is not widened: every process of the user would get the right, and a refused query reads Unknown, never Confirmed. Its verification waits for a native run or a later review.

### AUD-017-SEC018 — Medium — The tracer check accepted a walk cut short
