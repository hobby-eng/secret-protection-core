# AUD-018: An outside review of secret-protection-core 0.2.0 at `cd06231`

## Release decision

**Not ready for release until the native runs on Linux ARM64, macOS and Windows pass the [acceptance criteria of AUD-017](AUD-017-2026-11-25.md#acceptance-criteria) and the verifications below.** Review 1 found 1 High, 4 Medium and 7 Low findings, and the two reviews made two observations; all findings are fixed in `4cac7e6`, and AUD-018-SEC001, AUD-018-SEC002 and AUD-018-BLD001 block the release until their native runs.

The reviewed commit is `cd06231f7db09a1a9ecc51eafeecb22b07f9d81f` on `fix/aud-017`, version 0.2.0 before its release. It follows AUD-017's last remediation `f3da0e2` with `aaca588`, which passes the arguments of the `sendmsg` check as machine words on 32-bit Linux, and `cd06231`, which gives back an untouched work area without filling its pages.

### AUD-018-SEC001 — High — A Windows worker cannot open its own first thread

Since 0.2.0 the parent creates an AppContainer worker's first thread with `THREAD_ACCESS`, one entry for OWNER RIGHTS. The worker's own `enter` opened every listed thread by number with `OpenThread(MAXIMUM_ALLOWED)`, its own included. An AppContainer's access check also needs an entry for its package SID, which that list lacks, so the open is expected to fail: `NoMemoryReading` refused, and every `Worker::start` on Windows refused.

Fix in `4cac7e6`. `enter` sets and reads the access list of the calling thread through its pseudo handle, which needs no access check, as the integrity pass already did; other threads are still opened by number.

Verification: The Windows worker tests in native CI: a worker starts in its AppContainer and reports `NoMemoryReading` confirmed.

### AUD-018-SEC002 — Medium — macOS folder privacy misses symbolic links on the given path

On macOS `is_private` walked the folder's real parents through `..`. A symbolic link on the path as given, which another user owns or may replace, was not seen: `is_private` stayed true while that user could point the path the program writes by elsewhere.

Fix in `4cac7e6`. `settled_on_the_way` follows the given path name by name, links included: every folder a name is looked up in must be the user's or root's, writable by others only with the sticky bit, with no access list for anyone; a name in such a shared folder and every link must be the user's or root's; at most 32 links. macOS only, as before; Landlock holds the folder itself.

Verification: A native macOS run of the folder role, which makes a folder through a link in a folder others may write in and expects `is_private` false.

### AUD-018-API001 — Medium — macOS reads a missing TMPDIR as file writes allowed

When `TMPDIR` named a folder that does not exist, the probe's exclusive creation failed with NotFound, which counted as not refused: `NoFileChanges` read Refused although the sandbox refuses writes. The error is on the safe side, a protection reported missing.

Fix in `4cac7e6`. Only folders that exist are probed, each in turn: success means writes are allowed, a permission refusal means they are refused, any other error tries the next place, and none left reads Unknown. Test: on macOS the isolated role runs with `TMPDIR` naming a folder that does not exist and still reports `NoFileChanges` confirmed.

Verification: That test in a native macOS run.

### AUD-018-BLD001 — Medium — No native run on Windows, macOS and Linux ARM64 since 0.1.0, and untested paths

Windows, macOS and Linux ARM64 have run no test since 0.1.0, so AUD-016-SEC009 and the pending findings of AUD-017 wait. SGR mouse reports, `clear_stack` alone and a worker's request longer than its first 4 KiB buffer had no test.

Fix in `4cac7e6`. Tests: an SGR mouse report, pressed and released past column 223, stays out of a line; `clear_stack` alone clears what the work left below its caller; a worker serves a request of 5,000 bytes. The branch is pushed, so CI runs natively on Linux ARM64, macOS and Windows. The Windows console code keeps no test of its own: a CI runner has no console.

Verification: The native CI jobs pass on the pushed commit.

### AUD-018-DOC001 — Medium — Files over the line limit and stale documents

`tests/worker.rs` (822 lines of code) and `tests/isolation/linux.rs` (819) passed CORE-15's 800 without a `long:` note; the README counted 113 checks where the coverage report counts 114; TECHNICAL.md did not say that an untouched work area is given back unwiped; API.md names 0.1.1.

Fix in `4cac7e6`. Both test files carry a `long:` note with their reason; the README and the coverage report name the measured revision and its checks; TECHNICAL.md describes the drop of a work area. API.md describes the published 0.1.1, which is right until the release commit of 0.2.0 changes it together with the tag's digest.

Verification: Read at the fix commit.

### AUD-018-SEC003 — Low — Unix hidden input keeps flow control and stripping, misreads a non-waiting input, and drains twice

The hidden settings left `IXON`, `IGNCR` and `ISTRIP` as found: Ctrl+S and Ctrl+Q stayed flow control, a terminal set to ignore carriage returns swallowed Enter, and one that strips the eighth bit changed non-ASCII keys. An input set not to wait (`O_NONBLOCK`) failed with a misleading message, `terminal_for` took Linux's access mode 3, which serves ioctls alone, for both reading and writing, and a first drain that failed was followed by a second one on the way out.

Fix in `4cac7e6`. The hidden settings clear `BRKINT`, `IXON`, `IGNCR` and `ISTRIP` and read them back; an input set not to wait is refused before anything changes, and a drain that finds the input set so meanwhile reads it as empty; a descriptor counts for reading or writing only in that mode or read-write; the drain on the way out is armed only after the first one succeeded. Tests: keys arrive whole under those flags, a non-waiting input is refused, and a mode-3 descriptor is no terminal to use.

Verification: The Linux unit tests pass; the macOS run of the terminal role remains.

### AUD-018-SEC004 — Low — A folder's path keeps a final `/` or `/.`

`WritableFolder::create` kept a final `/` or `/.` in the path it stores, after which the check that the path still leads to the folder followed a link at its last name.

Fix in `4cac7e6`. The path is stored without them. Test: a folder made at `…/made/.` keeps `…/made`, byte for byte, and once the folder is moved away and a link to it put at `…/made`, the path no longer leads to it.

Verification: The unit test passes on Linux.

### AUD-018-SEC005 — Low — A fork during the Landlock layer's TSYNC gives a child the layer without its record

Between `landlock_restrict_self` with TSYNC and the store of `LAYERED_PROCESS`, a fork on another thread gave a child the layer but no record of it; a later `enter_with_folders` there would report `FolderWrites` confirmed while the inherited layer refuses the writes.

Fix in `4cac7e6`. Where an earlier secret or isolation put the gate of secret memory in place, the call holds it across the layer and its record, so such a fork waits; it never registers the gate itself, which among other threads would settle secret memory as unavailable for good. Without the gate, or when it stays busy past 100 ms, the window stays, as TECHNICAL.md says.

Verification: Review; the race is not reproducible in a test.

### AUD-018-API002 — Low — Windows finds a console for `write_secret` by its mode

`write_secret` took standard output for a console only when `GetConsoleMode` succeeded, which needs the read right; a console open only for writing got UTF-8 bytes, which it shows in its code page. The review also named unchecked lengths of `GetTokenInformation` and an unsplit `WriteConsoleW`.

Fix in `4cac7e6`. A console is a handle that `GetConsoleMode` accepts, or a character device for which it answers access denied, as a console open only for writing does; NUL, a file or a pipe answer otherwise and keep `WriteFile`. Not changed: a successful `GetTokenInformation` has written all it reports, and `WriteConsoleW` has had no 64 KiB limit since Windows 8, older than the policies this crate needs.

Verification: A native Windows run with a console.

### AUD-018-API003 — Low — macOS access-list kinds, a split list in HISTORY.md, and CI without dprint and ARMv5

`listed_access` counted only allowing entries, so an entry of an unknown kind passed as granting nothing; a blank line split a list of HISTORY.md in two; CI ran neither `dprint check` nor Clippy for a 32-bit Linux without this crate's filter. The review also asked for `proc_pidinfo` to be retried on EINTR.

Fix in `4cac7e6`. Every entry but a denying one counts as allowing; the second list has a heading of its own; CI installs dprint by its SHA-256 and checks the formatting, and `armv5te-unknown-linux-gnueabi` joins the targets that Clippy lints. Not changed: `proc_pidinfo` waits for nothing a signal could interrupt (CORE-54).

Verification: CI on the pushed commit; the access lists on macOS natively.

### AUD-018-FUN001 — Low — A Unix worker that ends just after its shutdown wait counts as not ended

When the worker ended by itself after the first wait ran out and was collected before the kill, `pidfd_send_signal` answered ESRCH, `terminate` returned false, and `finish` reported the worker as not ended.

Fix in `4cac7e6`. On Linux with a pidfd, `terminate` counts ESRCH as ended, so the second bounded wait reports the exit; macOS and the POSIX fallback have no stable handle to ask. Test: a child collected before the kill counts as ended.

Verification: The unit test passes on Linux.

### AUD-018-FUN002 — Low — A protected stack's size, a work area's debug text after fork, and the worker's buffer order

`run_on_protected_stack` raised the size to `PTHREAD_STACK_MIN` after rounding it to pages, which leaves it unaligned where that minimum is no whole page; the `Debug` text of a `WorkArea` read its bytes, which ends a child of `fork`; a worker allocated a larger request buffer before giving back the old one, holding both.

Fix in `4cac7e6`. The minimum comes first, then whole pages; `Debug` takes the length the pages record, without reaching them; the old buffer is dropped first. Test: a child of `fork` formats its parent's work area.

Verification: The fork test passes on Linux; the stack size on a 16 KiB page needs a native macOS run.

### Observations

- **AUD-018-SEC006, the steps of a TSYNC entry are not one atomic step.** A thread that puts in a seccomp filter of its own between `share_filters` and the filter's TSYNC makes the call stay short of the whole process, which reports `WholeProcess` refused; a thread with a Landlock layer of its own has it replaced. Both are written in TECHNICAL.md and fail closed.
- **AUD-018-SEC007, a thread an AppContainer worker starts after its default list changed cannot be opened by number.** Such a thread starts with the restricted list, as the first one does, so the worker cannot open it by number; one that appears between the change and the walk makes `NoMemoryReading` read as not confirmed and the start fail. It fails closed, needs a thread started in that instant, and TECHNICAL.md says so.
