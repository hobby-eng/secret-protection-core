### AUD-008-SEC001 — The pipe access list admits ordinary processes of the same user

Two independent allow entries grant the client access mask to the user SID and the package SID. For a normal desktop token the user entry can supply the requested access. The extra package entry does not require membership in that package for such a token. The low mandatory label also permits a low-integrity writer subject to the DACL. A different permitted local client that reaches the single instance first can abort startup. The subsequent PID comparison rejects the wrong peer before the parent admits any secret request. There is no demonstrated secret transfer.

Describe the actual DACL and retain the PID gate. If exclusive pre-connection access is required, establish it through the supported broker/package security model. Decide whether an unexpected first client should be recoverable. On native Windows validate the intended token, a regular same-user token, and the parent admission decision. A rejected peer must never receive application data.

Frozen locations. `src/os/windows/worker.rs:124`, `src/os/windows/worker.rs:52`, `src/os/windows/worker.rs:203`, `docs/TECHNICAL.md:166`. ### AUD-008-FUN001 — The client endpoint has no owner that closes it when serve returns

The worker uses CreateFileW once and constructs two File owners from that same raw handle. Wrapping both in ManuallyDrop suppresses both destructors. The handle acquired by this invocation is not a borrowed standard stream. When service ends or unwinds and the process stays alive, the endpoint remains open, consuming a handle and potentially delaying an EOF indication. Immediate process exit releases it.

Use one RAII File with borrowed reader/writer access, or keep two separately owned handles obtained by duplicating the first. Verify handle lifetime and peer EOF on normal return, I/O error and unwind while the worker process stays alive.

Frozen locations. `src/os/windows/worker.rs:457`, `src/os/windows/worker.rs:471`, `src/worker.rs:225`. [Reference 1](https://doc.rust-lang.org/std/os/windows/io/trait.FromRawHandle.html#safety)

### AUD-008-API001 — Malformed worker settings can still activate worker mode

The terminal field is true only for 1 and maps every other string, including malformed or empty values, to false. The common parser does not enforce the platform-specific channel shape. Windows checks its name only after Isolation::enter_with. The previous version already used a permissive flag comparison, and the new format and regression retain that behavior. A malformed environment value can select worker mode and run cleanup/isolation before the configuration error is recognized. The normal library-generated setting has the expected shape. This is distinct from descriptor ownership during an otherwise valid bootstrap.

Validate the exact supported flag and platform-specific transport shape before cleanup. Retain explicitly documented compatibility for settings the parent actually emits. Add parser tests for missing, invalid and platform-inapplicable fields, and verify the public entry takes no irreversible action on an invalid setting.

Frozen locations. `src/worker.rs:203`, `src/worker.rs:214`, `src/worker.rs:225`, `src/os/windows/worker.rs:450`.

## What still needs a Windows host

Microsoft documents the LOCAL pipe namespace for AppContainer/UWP and packaged deployments. This implementation fixes a global pipe prefix and accepts only that prefix. The reviewed topology uses an unpackaged Win32 server and a manually launched AppContainer. Its interoperability must be measured on each supported packaging profile. Neither a DACL nor a successful link establishes it; no universal launch failure was observed. [Microsoft UWP IPC](https://learn.microsoft.com/en-us/windows/uwp/communication/interprocess-communication#pipes) · [Microsoft Windows app IPC](https://learn.microsoft.com/en-us/windows/apps/develop/communication/interprocess-communication#pipes)

On a supported native Windows host, run the stock worker test executable from a directory readable and executable by the worker AppContainer. Use public sample data. Record OS build, packaging mode and diagnostic stage for a failure.

Verify a full public request/response and clean child exit, rejection before admission for a mismatched client, and channel closure when serve returns while the process remains alive. Include concurrent ordinary process launches and the actual deployment namespace.

The native pipeline owns these checks. On Linux, the worker tests exercise the Unix transport and the parser. No security conclusion about native ACL checks follows from that suite.

On the reviewed single-use server, generic behavior described for a disconnected, reused PIPE_NOWAIT instance was not treated as an observed initial-connect failure. The implementation does not create an overlapped pipe. Its poll can wait while a child stays alive without connecting, as the existing no-startup-deadline contract permits. [ConnectNamedPipe states](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-connectnamedpipe)
