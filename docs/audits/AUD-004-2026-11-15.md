### AUD-004-SEC001 — Default DLL search policy is presented as a universal allow-list

KnownLibrariesOnly can satisfy a strict requirement after the default search directories and image mitigations were set. Windows applies those directories to default name resolution. An explicit permitted local path or per-call search flags can select locations outside them. This matters to callers relying on an enforced directory boundary.

A host that requires directory-based DLL isolation may accept a weaker boundary. Name the actual default-search guarantee or enforce and verify an executable image policy matching the stronger promise.

On Windows check default resolution and explicit-path behavior independently. Require the exact policy intended by the caller.

### AUD-004-API001 — Concurrent macOS isolation calls can erase confirmation of the sandbox

Two callers can enter initialization together. A later refusal can overwrite an earlier success with false. Future strict checks can then reject an already sandboxed process. The sandbox itself remains active.

Strict workloads can become unavailable in a process that successfully entered the sandbox. Serialize initialization or publish success monotonically and consult the shared result after a competing refusal.

Test two initializers with one success and one refusal in both completion orders, then repeat on macOS.

Static review of the pinned implementation and its stated operating conditions. [src/os/apple.rs line 131](../../src/os/apple.rs#L131) · [src/os/apple.rs line 140](../../src/os/apple.rs#L140)

### AUD-004-API002 — The child-process policy ignores its secure-process exception

The Windows readback accepts the child-creation denial bit with no disallowed exception mask. The API defines a separate AllowSecureProcessCreation exception. If both are present, the reported blanket NoNewPrograms guarantee is stronger than the policy. This is limited to secure processes.

A strict caller can accept a narrower child-process restriction on a host with this exceptional policy. Reject the secure-process exception for the blanket guarantee, or report the narrower policy explicitly.

Check policy words with and without the exception, then compare with native readback.

### AUD-004-DOC001 — ClosedSecret availability of page sealing is overstated

The summary promises inaccessible pages between uses. The implementation correctly tracks access after a failed sealing attempt and supports a heap fallback that cannot close pages. Under those conditions idle bytes may remain readable.

Applications can assume idle secret pages are inaccessible when the platform or resealing attempt left them readable. Describe the fallible guarantee and show strict callers when to inspect is_closed, including after a use.

Check public guidance against the refused transition test and heap fallback.

## Interpretation

The stack checks requirements before the callback starts. Successful pthread_join precedes zeroization of the mapped stack and resumption of a Rust panic. Tests, Miri and the release assembly address different parts of this chain.

WebAssembly WorkArea uses try_reserve_exact and can return a failure. Native page locking and sealing are unavailable on this backend.

Windows socket status is derived from token/AppContainer capability information. The fixed-size TokenCapabilities query and the exact advertised distinction between socket creation and connectivity need native evidence. Treat this as an unresolved validation question.
