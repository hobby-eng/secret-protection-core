# AUD-016 — Four reviews of secret-protection-core 0.1.1 and their remediation

## Release decision

**Not ready for release until the fixes below are committed and the native runs on Linux ARM64, macOS and Windows pass every [acceptance criterion](#acceptance-criteria).** Four independent reviews read version 0.1.1 and the remediation that followed. Together they found 3 High, 10 Medium and 19 Low findings, one unconfirmed suspicion and two performance notes. No Critical defect was found, and no review found a memory-safety defect in the `unsafe` and FFI code.

The base is commit `fcca0b234266163ab2d7e0fc8d5aa2a4a0f66940`, tag `v0.1.1`, tree `a4caa9a4f24a8f0a22236e7a2badabbbbfb084a4`. The fixes are in commit `74bd18969ea85788ad05efbea8f5499d215eabb6`, so each finding is `fixed` with its verification pending: an independent check of that commit and the native runs. The stack clearing that MHFE needs is in the next commit, `ce54e89`.

### AUD-016-SEC001 — High — A same-user process can open the Windows worker before its access lists are set

`CreateProcessW` (`src/os/windows/worker.rs`, line 406) received null process and thread security attributes, and the worker set its restricted access list only later, in its own isolation (`src/os/windows.rs`, line 330). A new list does not revoke a handle opened before it, so a process of the same user that opened the worker with `PROCESS_VM_READ` in that interval could read its memory, the secret included. AUD-014-SEC007 had accepted that existing handles keep their rights; this finding shows that one can be opened while a worker starts. Confidence 8/10.

Fix: the process and its first thread are created with their access lists. A Windows test creates a suspended worker, reads both lists back and expects `OpenProcess(PROCESS_VM_READ)` from the test process to be refused.

### AUD-016-SEC002 — High — A macOS terminal worker can type into the user's shell and change other terminals

The sandbox profile (`src/os/apple.rs`, lines 60–68) granted `file-write*` and `file-ioctl` on `/dev/tty` and every `/dev/ttys[0-9]+`, and a terminal worker kept its controlling terminal (`src/worker.rs`, lines 288–290). XNU lets a process that is not root use `TIOCSTI` on its controlling terminal when the descriptor is readable, so compromised worker code could type a command line that the user's shell runs outside the sandbox, while `NoNewSockets` and `NoFileChanges` read Confirmed. Any sandboxed process could also write to the user's other terminals and change their mode, owner or attributes. A terminal worker also received standard error as it was, which under systemd is a journald socket (`src/os/unix.rs`, lines 375–383). The sandbox language filters `file-ioctl` by path only, not by request.

Fix: every worker leaves its parent's session. A worker on the terminal gets the program's terminal, opened anew by name without becoming a controlling terminal, as its standard error, or `/dev/null`. The profile writes data only to `/dev/null` and the process's own terminal, allows ioctls only there and refuses reading other terminals. A test runs a worker on a new pseudo-terminal, expects `TIOCSTI` to be refused and finds no input waiting.

### AUD-016-SEC003 — High — Linux enters the user namespace before it forbids reading its memory

`src/os/linux.rs` (line 240) ran `unshare(CLONE_NEWUSER | …)` before `PR_SET_DUMPABLE 0` (lines 244–252). In a namespace the user owns, every process of that user holds `CAP_SYS_PTRACE`, which passes Yama's exception, so with the default `ptrace_scope=1` another process of the user could open `/proc/<pid>/mem` in that window and keep the descriptor, while `NoMemoryReading` read Confirmed.

Fix: the dumpable flag and the core limit are cleared before the namespace step.

### AUD-016-API001 — Medium — Worker start and calls can block without end

`Worker::start` and `Worker::call` (`src/worker.rs`, lines 60–64, 109–120 and 129–186) had no deadline. A stalled start or a handler that never returns held the calling thread. Confidence 9/10.

Fix: `Worker::start_within` and `Worker::call_within`. When the deadline passes the worker is ended and the start or call fails with `TimedOut`; later calls fail with `BrokenPipe`. Unix polls the pipes; Windows ends the worker from one watchdog thread per call, and its start also bounds the wait for the pipe connection. A test calls a worker that sleeps.

### AUD-016-API002 — Medium — `enter_requiring` accepts protection confirmed for one thread

`Isolation::enter_requiring` (`src/protect.rs`, lines 324–355) accepted an outcome confirmed only for the calling thread; a caller needing every thread had to read each measure's `reach`, as `docs/API.md` (lines 153–177) said. Confidence 8/10.

Fix: `Isolation::enter_requiring_process_wide` and `Isolation::require_process_wide` require each protection and `WholeProcess` with process reach, the rule of worker admission, and list every unmet protection. Unit and integration tests cover a thread-scoped refusal and a process of one thread.

### AUD-016-BLD001 — Medium — A release does not wait for the full test matrix, fuzzing and the advisory check

`.github/workflows/release.yml` (lines 3–57) packaged on Linux independently of the native matrix in `ci.yml`, fuzzing and RustSec. Confidence 9/10.

Fix: the release workflow calls the CI and audit workflows and runs the three fuzz targets; packaging needs all three.

### AUD-016-SEC004 — Medium — `SignalsToSelfOnly` passes signals sent through `fcntl` ownership

The signals rule (`src/os/linux/seccomp.rs`, lines 265–282) did not cover `fcntl(F_SETOWN)` or `F_SETOWN_EX` with `O_ASYNC`, through which the kernel signals any process or group of the user.

Fix: with the option, the filter refuses both commands; tested.

### AUD-016-API005 — Medium — A deadline can be lost: an unrepresentable one and the Unix launch wait

`Instant::now().checked_add(deadline)` (`src/worker.rs`, lines 88–98 and 170–177) gives no deadline for a `Duration` the clock cannot hold, such as `Duration::MAX`, and the Unix launch ignored the deadline while waiting for `posix_spawn` (`src/os/unix.rs`, line 312). Confidence 10/10.

Fix: the Unix start bounds the wait for the launcher with the deadline; the documentation says that a deadline too far ahead for the clock waits without one, which is the same as waiting for it. A test starts a worker with a zero deadline and expects `TimedOut`.

### AUD-016-DOC002 — Medium — The README describes the terminal worker, installation and coverage wrongly

`README.md` (lines 10, 46 and 61) promised a worker its controlling terminal, named only a Git dependency, and gave the coverage figure without its revision and report. Confidence 10/10.

Fix: the README describes the terminal on standard error without a controlling terminal, crates.io and a signed tag, and names the measured revision `e7b0d38` with a link to `docs/COVERAGE.md`.

### AUD-016-DOC001 — Low — Third-party notices name older versions than the lockfile

`THIRD_PARTY_NOTICES.md` named zeroize 1.9.1 and landlock 0.4.7; the lockfile of 0.1.1 holds 1.9.2 and 0.4.8. Fix: the notices name the locked versions, and CI checks them (see BLD003).

### AUD-016-BLD002 — Low — Compatible version ranges can resolve to untested versions

Since 0.1.1, `Cargo.toml` takes compatible ranges, so a program can resolve newer releases than the tested `Cargo.lock`. Accepted: compatible ranges let a program share these dependencies, and reviews 2 and 3 agree that they are normal for a library; `docs/API.md` names the tested lockfile.

### AUD-016-SEC005 — Low — `FileLocksRefused` leaves leases open

The lock commands (`src/os/linux/seccomp.rs`, line 185) omitted `F_SETLEASE`, which shows in `/proc/locks` and stalls other processes that open the file. Fix: refused with the option; tested.

### AUD-016-SEC006 — Low — The filter allows calls that act on other processes

The filter's description promised to refuse calls on other processes, but `prlimit64` (which can raise another process's soft core limit), `setpriority`, `sched_setaffinity`, `ioprio_set` and `move_pages` (a page-residency oracle) stayed allowed, and `PR_SET_NAME` sets a name anyone can read.

Fix: limits, scheduling, page placement and robust-list reads act only on the process itself; `kcmp`, `process_madvise` and `ioprio_set` are refused; tested. The process name and command line stay readable by other processes, which the documentation now says.

### AUD-016-SEC007 — Low — The kernel can copy secret pages and free the old ones unwiped

Work areas and protected stacks lacked `MADV_NOHUGEPAGE`, so a khugepaged collapse could copy them, and compaction moves locked anonymous pages by default. Fix: protected stacks ask for small pages; the documentation names the residue for work areas and the kernel settings `init_on_free=1` and `vm.compact_unevictable_allowed=0`.

### AUD-016-SEC008 — Low — A worker is started from the program path, looked up again

A file put at the program's path would receive the secrets. Fix: Linux starts `/proc/self/exe`; macOS and Windows still start the path, which the documentation states.

### AUD-016-SEC010 — Low — The macOS sandbox grants `/dev/tty` to a process without a terminal

`profile()` (`src/os/apple.rs`, lines 62–63) always allowed writes and ioctls on `/dev/tty`, so a process that isolated itself with its standard streams redirected kept `TIOCSTI` on a controlling terminal. Confidence 9/10. Fix: a process none of whose standard streams is a terminal gets no terminal rule; the ioctl rule is left out entirely, since a rule without a path would allow every ioctl.

### AUD-016-API004 — Low — Public fields of `Isolation` can drift from its outcomes

The public `bool` fields can be changed without changing the outcomes that `has` and `require` read. Fix: the documentation says the fields are a copy made at entry, for reading, and that no check reads them. Read-only accessors would change the public interface and are left for a breaking release.

### AUD-016-ARC001 — Low — Two files exceed 800 lines of code (CORE-15)

`src/os/unix.rs` held 810 and `tests/worker.rs` 887 lines of code. Fix: the parent's side of a Unix worker moved to `src/os/unix/worker.rs`, as Windows already has `src/os/windows/worker.rs`, and the Unix test roles to `tests/worker/unix.rs`.

### AUD-016-ARC002 — Low — Duplicated declarations and a descriptor parsed again per thread (CORE-10)

`pthread_atfork` was declared twice, the page size read twice without a check, Windows had two wrappers of a security descriptor, and the thread walk parsed the same SDDL text for every thread. Fix: one declaration, one page-size function, one descriptor type, and one parse per walk.

### AUD-016-BLD003 — Low — The fuzz dependency is not pinned, the notices check misses cases, fuzzing ignores the lockfile

`libfuzzer-sys` took a range in an unpublished workspace (CORE-25); the notices check missed a second version on one line and packages missing from the notices; `cargo fuzz run` has no `--locked`. Fix: `=0.4.13`; CI compares the notices with the library's dependency tree in both directions; the release checks the fuzz lockfile with `cargo fetch --locked` before fuzzing.

### AUD-016-FUN001 — Low — Tests miss the start deadline, the process-wide entry, several filter rules and macOS terminals

Fix: tests for a start with a zero deadline, `enter_requiring_process_wide` in a process of one thread and `require_process_wide` in a thread, `migrate_pages`, `get_robust_list` and the `sched_set*` calls on another process, and, on macOS, reading, writing and changing the mode of a terminal that is not the process's own.

### AUD-016-SEC011 — Medium — Linux enters a user namespace after an unconfirmed dumpable change

Review 4, AUD-017-SEC001, release blocking. The fix of SEC003 cleared the dumpable flag before the namespace step but did not check the answer (`src/os/linux.rs`, lines 230, 269 and 637). A host policy that refuses the `prctl` while it allows user namespaces would leave the process dumpable inside a namespace its user owns. Fix: the namespace step runs only when the flag reads back as cleared.

### AUD-016-SEC012 — Medium — The signal option leaves asynchronous terminal signalling outside its check

Review 4, AUD-017-SEC002, release blocking. With `O_ASYNC` set on a terminal, the tty driver makes the terminal's foreground process group the owner by itself (`drivers/tty/tty_io.c`), so input signals another group while `SignalsToSelfOnly` reads Confirmed, unless a Landlock signal scope applies. Fix: with the option the filter also refuses `F_SETSIG` and `F_SETFL` with `O_ASYNC`; `F_SETFL` for other flags, such as `O_NONBLOCK`, still works. A descriptor that had `O_ASYNC` before isolation keeps it, which the documentation states. Tested.

### AUD-016-API006 — Medium — Windows can accept or wait for a worker past its deadline

Review 4, AUD-017-API001, release blocking. The profile, the pipe and `CreateProcessW` ran before the first deadline check, and the watchdog decided by its channel, so work that finished late could pass when the watchdog ran late (`src/os/windows/worker.rs`, lines 44, 194 and 317). Fix: the start checks the deadline before the calls that cannot be cut short and after the connection; the watchdog checks expiry before the work and decides by the time the work ended, ending the worker either way. The public contract says that the launch call itself cannot be cut short.

### AUD-016-API007 — Medium — A late Unix launch can leave the child and its waiter alive

Review 4, AUD-017-API002, release blocking. When a start gave up before `posix_spawn` returned, the launcher thread waited for the child without ending it, so a worker stalled before its pipes stayed alive with its waiter (`src/os/unix/worker.rs`, line 72). Fix: the launcher ends an abandoned child through its stable handle where there is one (a pidfd on Linux); without one the child ends when it finds its pipes closed.

### AUD-016-SEC013 — Low — The file lock option leaves delegated leases available

Review 4, AUD-017-SEC003. Linux 7.0 added `F_SETDELEG` (1040), which takes a lease through the same machinery. Fix: refused with `refuse_file_locks`; tested.

### AUD-016-SEC014 — Low — A child of `fork` keeps the installer's process number in the process rules

Review 4, AUD-017-SEC004. The process rules allowed 0 and the installer's number, which a continuing child of `fork` inherits as its parent's. Fix: only 0, the caller; a number is refused even for the process itself. Tested.

### AUD-016-SEC015 — Low — The macOS read rule does not exclude every terminal device

Review 4, AUD-017-SEC005. The read exclusion named only `/dev/ttysN`; `/dev/tty`, legacy BSD terminals and serial devices stayed readable. Fix: reads exclude every name under `/dev` that starts with `tty`, `pty`, `cu.` or `console`; a process with a terminal among its standard streams gets that terminal and `/dev/tty` back.

### AUD-016-BLD004 — Low — The release checks the fuzz lockfile before a run that can change it

Review 4, AUD-017-BLD001. `cargo-fuzz` has no `--locked` and could resolve anew after the checked fetch. Fix: the release fails when `fuzz/Cargo.lock` differs after fuzzing.

### AUD-016-BLD005 — Low — The notices check compares partial version strings

Review 4, AUD-017-BLD002. The forward check matched a substring and the reverse check numeric triples only. Fix: CI builds the exact `name vVERSION` pairs of `cargo tree` and of the notices, prerelease and build suffixes included, and requires the two lists to be equal.

### AUD-016-DOC003 — Low — The package verification example checks no source commit

Review 4, AUD-017-DOC001. Fix: the example passes `--source-digest` with the commit of the signed tag and says how to read it.

### AUD-016-DOC004 — Low — The security policy omits the Windows console boundary

Review 4, AUD-017-DOC002. Fix: `SECURITY.md` says that a process keeping a writable console can put input into it (`WriteConsoleInput`) where Windows allows, and that a worker has no console.

### Read-back by review 4

It reopened SEC003, SEC004, SEC005, SEC006, SEC010, API001, API005 and BLD003 for the follow-ups above (SEC011 to SEC015, API006, API007, BLD004 and BLD005), which this record closes in the working tree. ### Review of the remediation of review 4 (CORE-53)

An independent read-only Claude agent reviewed the fixes of review 4 in the working tree before anyone else did, as CORE-53 now asks of every round of fixes. It confirmed SEC011 to SEC015, API006 (the start), BLD004, BLD005, DOC003 and DOC004, modelled the new filter blocks for five option sets, and found seven Low defects, all fixed:

- The Unix launcher handed the child through a channel with a one-place buffer, so a child sent just after the start gave up was dropped unended. The hand-over now has no buffer (`deliver`), nothing is launched once the deadline has passed, and a test ends and collects an abandoned child.
- The timed calls promised that the worker is ended. They now say that it is given up and terminated where a stable handle exists, and that the call returns after the shutdown wait.
- A Unix timed exchange could accept an answer read just past the deadline. The clock decides at the end, as on Windows.
- The Windows watchdog could end a worker whose work had ended in time. One shared state now decides which came first; a Windows test checks both sides of the deadline.
- The documentation of the options did not name leases and delegations, the refusal of `O_ASYNC` and its effect on signal-driven I/O, the refusal of thread numbers, or `setpriority` for groups and users.
- The signal option's text did not exclude the job-control signals the kernel sends to a process group from a controlling terminal. It does now; a worker has none.
- Tests were missing for a refused dumpable flag, for the signal option on its own, for a launch that finishes after its start gave up, and for the Windows completion boundary. They exist now.

### Observations

- **AUD-016-SEC009, unconfirmed.** Whether a `VirtualLock` survives `VirtualProtect(PAGE_NOACCESS)` is undocumented, so a closed secret's pages might leave the working set. A Windows test now reads the working-set flags of a closed secret; only a native run decides.
- **AUD-016-API003, performance.** Every frame made a new `Secret` on both sides, on Linux secret memory with its setup and a TLB flush when given back. Fix: the worker keeps one request buffer, one page or the limit, grown for a larger request and wiped after each. The parent's reply is the caller's own `Secret` and stays.
- **AUD-016-ARC003, performance.** On Windows each read and write with a deadline started a watchdog thread, four per call. Fix: one per call and one per start.

## Acceptance criteria

The guarantees that MHFE and MnemoCode will rely on, each with the test that confirms it and the systems where that test must pass before release.

| Guarantee | Test | Must pass on |
| --- | --- | --- |
| Secrets stay out of swap and dumps where the system grants it, wipe on drop, and report each property | `secret_memory`: pages kept out of swap and core dumps, lock limits, work area, fork | Linux x86-64 and ARM64, macOS, Windows |
| A locked closed secret stays locked while closed | `secret_memory`: the closed secret's working-set flags | Windows (SEC009) |
| Isolation reports only confirmed outcomes with their reach, and the process-wide rule refuses one thread | `isolation`: a process of one thread, an isolated thread; unit test of `require_process_wide` | Linux x86-64 and ARM64, macOS, Windows |
| The Linux filter refuses new sockets, `io_uring`, programs, file changes, `TIOCSTI` and calls on other processes, and with the options locks, leases, delegations, signal owners and `O_ASYNC` | `isolation`: an isolated thread, options with one more filter | Linux x86-64 and ARM64 |
| Another process cannot read an isolated process's memory | `isolation`: a process of one thread, read from outside | Linux, Windows |
| The macOS sandbox refuses the network, file writes and other terminals | `isolation`: a process of one thread on macOS | macOS |
| A Windows worker is created with its access lists and cannot be opened for reading | unit test `a_worker_is_made_with_its_access_lists` | Windows |
| A worker starts clean, is admitted only process-wide, has no controlling terminal and cannot type into a terminal | `worker`: start-up roles, without `setsid`, on a terminal | Linux, macOS; the terminal worker is not offered on Windows |
| A start or call past its deadline fails with `TimedOut` in bounded time and ends the worker | `worker`: a call past its deadline | Linux, macOS, Windows |

| A release is made only from a tag whose checks, audit and fuzzing passed with the checked-in lockfiles | `release.yml` on the tag | GitHub Actions |

MHFE also needs `refuse_file_locks`, `refuse_sendmsg` and `signals_to_self_only`, and on Windows `refuse_dynamic_code` and `microsoft_signed_only`; `lock_all_memory` stays off for its 2 GiB Argon2 area.
