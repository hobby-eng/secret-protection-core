## Findings

### AUD-009-SEC001 — High — A worker is called clean without a look at what it holds when it comes to serve

- **Reviewer's identifier:** SEC-01.
- **Affected files:** `src/os/unix.rs`, `src/worker.rs`.
- **Evidence:** After `close_range` succeeded before `main`, the check returned true without a listing.
- **Reproduction:** A program opens a file in `main` before it calls `serve`, on a kernel with `close_range`.
- **Expected:** A worker that holds a descriptor besides its standard streams says its start was not clean and takes no request, as the documentation of `serve` says.
- **Observed:** The worker reported a clean start.
- **Impact:** A descriptor opened before `serve` stays usable after the isolation, which refuses only new ones: a way out of the worker that its report does not show.
- **Recommended fix:** Always list the open descriptors before the worker is called clean.
- **Required verification:** A worker with a descriptor of its own must report an unclean start.

### AUD-009-SEC002 — Medium — Any text in the worker's variable closes the inherited descriptors before main

- **Reviewer's identifier:** SEC-02.
- **Affected files:** `src/os/unix.rs`.
- **Evidence:** The function tested only whether the variable was set.
- **Reproduction:** Start a program that links the crate with the variable set to an empty or malformed text and with an inherited descriptor above standard error.
- **Expected:** A text that `serve` does not take leaves the program as it is.
- **Observed:** Every descriptor above standard error was closed before `main`, and the program then ran as one that is no worker.
- **Impact:** A program that got a descriptor from its parent, such as an activation socket, loses it.
- **Recommended fix:** Check that the variable holds a well-formed setting before closing.
- **Required verification:** A malformed text must close nothing; a setting must still close what was inherited.

### AUD-009-SEC003 — Medium — A process of the same user that takes the worker's pipe first stops the start

- **Reviewer's identifier:** SEC-03.
- **Affected files:** `src/os/windows/worker.rs`.
- **Evidence:** The pipe's access list names the user, and the pipe has one instance.
- **Reproduction:** Another process of the user opens the pipe between its creation and the worker's own connection.
- **Expected:** The start of a worker does not depend on other processes of the user.
- **Observed:** The parent found another process number, sent nothing, and the start failed.
- **Impact:** Denial of service by a process of the same user. No secret is sent.
- **Recommended fix:** Name only the AppContainer in the access list, or use several instances or inherited handles.
- **Required verification:** On Windows: a client that takes the pipe first must not stop the start.

### AUD-009-FUN001 — Medium — The Apple section of the function that runs before main does not name its kind

- **Reviewer's identifier:** SEC-04.
- **Affected files:** `src/os/unix.rs`.
- **Evidence:** The link section was given as `__DATA,__mod_init_func`.
- **Reproduction:** Build a worker for macOS with a toolchain that does not take the bare section name for one of that kind.
- **Expected:** The function runs before `main` on every Apple toolchain.
- **Observed:** Not observed: the Apple code had not run.
- **Impact:** A worker that keeps what it inherited. It then lists the descriptors and reports an unclean start, so the failure is a worker that does not start.
- **Recommended fix:** Name the section's kind, or close the descriptors when `serve` is called.
- **Required verification:** On macOS: a worker must hold nothing of a descriptor its parent left open.

### AUD-009-FUN002 — Low — Without /dev/null the worker's streams do not end when it serves no more

- **Reviewer's identifier:** SEC-05.
- **Affected files:** `src/os/unix.rs`.
- **Evidence:** The drop of the streams did nothing when /dev/null had not been opened.
- **Reproduction:** A worker under a policy that refuses opening /dev/null stops serving and does not end.
- **Expected:** The parent sees the end of the pipes when `serve` returns.
- **Observed:** The pipes stayed open for as long as the worker lived.
- **Impact:** A call of the parent waits for the worker's end.
- **Recommended fix:** Close the descriptors when /dev/null is not there.
- **Required verification:** A call to such a worker must fail at once.

### AUD-009-SEC004 — Low — Anonymous secret pages may be joined into huge pages

- **Reviewer's identifier:** SEC-06.
- **Affected files:** `src/os/unix.rs`.
- **Evidence:** No call marked the pages.
- **Reproduction:** A kernel that joins small pages into huge ones copies a secret's pages and frees the old ones as they are.
- **Expected:** A secret's bytes stay on the pages it was given.
- **Observed:** Not observed; the report reasons from the kernel's behaviour.
- **Impact:** Copies of secret bytes in freed pages, within reach of whoever reads physical memory.
- **Recommended fix:** Mark anonymous secret pages `MADV_NOHUGEPAGE`.
- **Required verification:** The mapping of a secret on anonymous pages must carry the flag.

## 3. Detailed Vulnerability Findings

### SEC-01: Descriptor Sanitization Bypass in `inherits_nothing()` via `SHED_AT_ONCE`
- **Severity**: **High** (CVSS: 7.1 / CVSS:4.0: AV:L/AC:L/AT:N/PR:L/UI:N/VC:H/VI:N/VA:N)
- **Location**: `src/os/unix.rs:372`, `src/worker.rs:241`
- **Description**:
  To protect workers against inherited file descriptors, `shed_inherited()` is installed into `.init_array` (running before `main`). On Linux systems supporting `close_range`, `shed_inherited()` executes:
  ```rust
  if close_range(FIRST_UNEXPECTED, u32::MAX, 0) == 0 {
      SHED.store(SHED_AT_ONCE, Ordering::Relaxed);
      return;
  }
  ```
  Later, when the worker executes `Worker::serve(channel, task)`, it calls `inherits_nothing()` to verify that no unexpected descriptors $> 2$ are open:
  ```rust
  pub(crate) fn inherits_nothing() -> bool {
      if SHED.load(Ordering::Relaxed) == SHED_AT_ONCE {
          return true;
      }
      listed_descriptors().is_empty()
  }
  ```
  **The Flaw**:
  `SHED_AT_ONCE` immediately returns `true` without scanning `/proc/self/fd` or `/dev/fd`. If application initialization code running in `main()` *between* `.init_array` and `Worker::serve()` opens files, network sockets, IPC handles, or logging channels (e.g., via static constructors, framework telemetry, or logger setup), those descriptors remain open in the worker process.
  Because `inherits_nothing()` returns `true`, `Worker::serve` reports `clean = true` over IPC and proceeds to accept and process secrets in an environment holding open descriptors.
- **Impact**:
  A worker process holding unintended descriptors can leak secret material (or allow external processes to read/write worker state through shared pipes/sockets), violating the core invariant that unisolated or descriptor-leaking workers are marked unclean and refused.
- **Remediation**:
  `inherits_nothing()` must always perform an empirical check via `listed_descriptors().is_empty()`. `SHED_AT_ONCE` indicates that pre-`main` shedding succeeded, but does *not* prove that post-`main` code has not opened new descriptors prior to `serve()`.

### SEC-02: Pre-`main` Descriptor Destruction & DoS via Unsanitized Environment Variable
- **Severity**: **Medium** (CVSS: 5.5 / CVSS:4.0: AV:L/AC:L/AT:N/PR:L/UI:N/VC:N/VI:N/VA:H)
- **Location**: `src/os/unix.rs:318-345`
- **Description**:
  The constructor hook `shed_inherited()` executes unconditionally in every process linking `secret-protection-core`:
  ```rust
  let channel = libc::getenv(c"SECRET_PROTECTION_CORE_WORKER".as_ptr());
  if channel.is_null() {
      return;
  }
  // Immediately executes close_range(3, u32::MAX, 0)
  ```
  If any parent or ambient environment sets `SECRET_PROTECTION_CORE_WORKER` (even to an empty string `""` or invalid text), `shed_inherited()` unilaterally destroys all file descriptors $> 2$ before `main()` executes.
- **Impact**:
  1. Any application utilizing systemd socket activation (file descriptor 3), inherited pipes, or pre-opened database connections that happens to have this variable in its environment has its descriptors silently obliterated before application code can inspect or validate them.
  2. If an unprivileged subprocess or attacker in the same process tree controls environment variables, they can inject `SECRET_PROTECTION_CORE_WORKER=` and cause permanent, unrecoverable denial of service or data corruption on startup.
- **Remediation**:
  Validate that `channel` points to a non-empty, valid channel identifier (e.g., hexadecimal or UUID matching the crate's channel naming format) before executing `close_range`. If the format is invalid, abort immediately or defer shedding until `Worker::serve()` is called explicitly.

### SEC-03: Windows Named Pipe Local Denial of Service Window for Same-User Processes
- **Severity**: **Medium** (CVSS: 5.3 / CVSS:4.0: AV:L/AC:H/AT:P/PR:L/UI:N/VC:N/VI:N/VA:H)
- **Location**: `src/os/windows/worker.rs:124-142`
- **Description**:
  In `AUD-008-SEC001`, the Windows worker named pipe DACL was updated to restrict client access using SDDL:
  ```text
  D:P(A;;CLIENT_ACCESS;;;UserSID)(A;;CLIENT_ACCESS;;;PackageSID)S:(ML;;NW;;;LW)
  ```
  The DACL includes `(A;;CLIENT_ACCESS;;;UserSID)`. This permits any process running under the same user account (even untrusted applications running at Low Integrity) to connect to `\\.\pipe\secret-protection-core.<nonce>`.
  When `Worker::start()` spawns the child process, there is a race window of 10–50 ms before the genuine worker connects.
  In `WorkerStream::accept()`:
  ```rust
  if client_pid(&pipe) != Ok(worker_pid) {
      return Err(io::Error::new(io::ErrorKind::ConnectionRefused, "worker was not the client"));
  }
  ```
  While `accept()` correctly refuses unauthorized clients and does not transmit secrets, connecting to the single-instance named pipe consumes the pipe instance. The genuine worker subsequently receives `ERROR_PIPE_BUSY` or connection failure, causing worker startup to abort with `ConnectionRefused`.
- **Impact**:
  Any local unprivileged script or process under the same user session can monitor pipe creation or guess/enumerate pipe names and force all `secret-protection-core` worker invocations to abort.
- **Remediation**:
  1. Since the worker runs inside an AppContainer with `PackageSID`, omit `UserSID` from the client DACL and permit *only* `PackageSID` (and the parent's logon session SID / `OWNER_RIGHTS`).
  2. Alternatively, create the pipe with multiple instances or pass the pipe handle directly to the child process via handle inheritance (`STARTUPINFOEX` with `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`) rather than using a global named pipe namespace.

### SEC-04: Deprecated Mach-O Linker Section `__DATA,__mod_init_func` on macOS
- **Severity**: **Medium** (Reliability / Portability Defect)
- **Location**: `src/os/unix.rs:364-370`
- **Description**:
  For Darwin targets, the crate attempts to hook pre-`main` execution via:
  ```rust
  #[cfg_attr(target_vendor = "apple", link_section = "__DATA,__mod_init_func")]
  static SHED_POINTER: unsafe extern "C" fn() = shed_inherited;
  ```
  Modern Apple toolchains (Xcode 13+, macOS 12 Monterey and later) have deprecated `__DATA,__mod_init_func`. Modern `ld64` and `lld` expect `__DATA_CONST,__mod_init_func` with explicit section attributes (`S_MOD_INIT_FUNC_POINTERS`).
  Furthermore, because `SHED_POINTER` is not referenced elsewhere in Rust code, Apple's linker with `-dead_strip` enabled (the default for release builds in Cargo) strips `SHED_POINTER`, causing `shed_inherited()` to never execute on macOS.
- **Impact**:
  On macOS, descriptor shedding prior to `main` fails silently, leaving `SHED` set to `SHED_NEVER`. Workers then fall back to scanning `/dev/fd`, but if `/dev/fd` is inaccessible or restricted, descriptor shedding is completely bypassed.
- **Remediation**:
  Use `#[used]` on `SHED_POINTER`, target `__DATA_CONST,__mod_init_func`, or prefer explicit descriptor shedding at worker entry (`Worker::serve`) rather than fragile linker-section magic.

### SEC-05: Silent Failure in `WorkerStreams::drop` When `/dev/null` Cannot Be Reopened
- **Severity**: **Low**
- **Location**: `src/os/unix.rs:591-602`
- **Description**:
  When `WorkerStreams` is dropped, it attempts to redirect `stdin`, `stdout`, and `stderr` to `/dev/null` using a cached file descriptor `nowhere`. If opening `/dev/null` failed during `worker_streams()` (which can occur if Landlock or mount namespaces restricted filesystem access), `nowhere` is `None`.
  In `WorkerStreams::drop`:
  ```rust
  let Some(nowhere) = self.nowhere else {
      return;
  };
  ```
  If `nowhere` is `None`, standard streams are not redirected, and the worker process may retain open pipe descriptors, preventing the parent from detecting EOF on stream termination.
- **Remediation**:
  If `nowhere` is `None`, fall back to closing descriptors 0, 1, and 2 directly (`libc::close(0); libc::close(1); libc::close(2);`).

### SEC-06: Missing `MADV_NOHUGEPAGE` on Secret Allocations
- **Severity**: **Low** (Hardening)
- **Location**: `src/os/linux.rs:170-220`
- **Description**:
  When Linux Transparent Huge Pages (THP) are enabled in `always` mode or under memory pressure, the kernel `khugepaged` daemon attempts to collapse contiguous 4KB anonymous pages into 2MB huge pages.
  If secret memory allocated via `Pages::new` or `WorkArea` is collapsed into a huge page, subsequent calls to `mprotect(..., PROT_NONE)` on guard pages or sub-regions may split huge pages unexpectedly, trigger high latency, or cause unzeroed memory fragments to linger in kernel hugepage caches.
- **Remediation**:
  Issue `libc::madvise(pointer, bytes, libc::MADV_NOHUGEPAGE)` upon allocating anonymous secret pages on Linux.

### SEC-07: Thread-Safety Invariant in `ClosedSecret::open` Under Concurrency
- **Severity**: **Low / Design Invariant**
- **Location**: `src/protect/closed.rs:88-125`
- **Description**:
  `ClosedSecret` enforces memory access permissions using virtual memory protections (`PROT_NONE` <-> `PROT_READ` / `PROT_READWRITE`). `mprotect` operates on page boundaries process-wide, not thread-local.
  `ClosedSecret` correctly requires `&mut self` for opening and reading:
  ```rust
  pub fn open<R>(&mut self, work: impl FnOnce(&[u8]) -> R) -> R
  ```
  Because Rust's ownership rules guarantee exclusive access via `&mut self`, no other thread can hold a reference to the same `ClosedSecret` simultaneously. However, if two separate `ClosedSecret` instances share the same virtual memory page, toggling protection on one instance would affect the other.
  **Verification**:
  Inspection of `src/os/unix.rs` and `src/os/windows.rs` confirms that every `Pages` allocation rounds up to full system page multiples and places `PAGE_SIZE` guard pages before and after the data payload. Therefore, page sharing between distinct secrets is physically impossible. This invariant is sound.

## 4. Architectural & Component Review

### 4.1 Memory Isolation (`Secret`, `WorkArea`, `ClosedSecret`)
- **Zeroization**: `zeroize_bytes` correctly uses `core::sync::atomic::compiler_fence` and `read_volatile` checks to defeat dead-store elimination (DSE).
- **`memfd_secret` Integration**: Linux implementation correctly manages `SYS_memfd_secret`, passes `O_CLOEXEC`, sets `ftruncate`, and handles `pthread_atfork` locks. This is the gold standard for Linux secret memory.
- **Guard Pages**: Every allocation includes leading and trailing guard pages configured with `PROT_NONE` (`PAGE_NOACCESS`), protecting against buffer over-read and linear stack/heap underflow/overflow attacks.

### 4.2 Linux & Android Isolation (`os/linux.rs`, `os/linux/seccomp.rs`)
- **Seccomp-BPF Filter**: The BPF program strictly filters architecture (`calls::ARCH`), blocks x32 ABI attempts (`calls::X32_BIT`), forbids dangerous syscalls (`ptrace`, `process_vm_writev`, `pidfd_getfd`, `execve`, `io_uring_*`), and parses open flags to forbid write operations (`WRITE_FLAGS`). Jump offsets and instruction sequencing were verified and found completely sound.
- **Landlock Sandboxing**: Seamlessly probes Landlock ABI versions 1 through 5, enforcing complete filesystem access denial (`HANDLED_ACCESS_FS`) when enabled.
- **Dumpability & Tracer Defense**: Correctly issues `prctl(PR_SET_DUMPABLE, 0)` and verifies tracer absence via `/proc/self/status` (`TracerPid: 0`).

### 4.3 Windows Isolation (`os/windows.rs`, `os/windows/worker.rs`)
- **Job Objects**: Limits processes via `JobObjectExtendedLimitInformation` with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, ensuring that child workers are terminated if the parent crashes.
- **Mitigation Policies**: Accurately enables:
  - `PROCESS_MITIGATION_IMAGE_LOAD_POLICY` (`NoRemoteImages`, `NoLowMandatoryLabelImages`, `PreferSystem32Images`).
  - `PROCESS_MITIGATION_BINARY_SIGNATURE_POLICY` (`MicrosoftSignedOnly`).
  - `PROCESS_MITIGATION_STRICT_HANDLE_CHECK_POLICY`.
  - `PROCESS_MITIGATION_CHILD_PROCESS_POLICY` (prevents worker from spawning sub-processes).
- **AppContainer Sandboxing**: Uses low-privilege capability SID structures and restricted SID tokens.

### 4.4 Stack Protection (`run_on_protected_stack`)
- Allocates independent 256KB stack areas bracketed by guard pages.
- Uses architecture-specific assembly (`asm!`) on x86_64 and AArch64 to pivot the stack pointer (`RSP`/`SP`), align to 16 bytes, invoke closures across an `extern "C"` boundary, catch panics via `catch_unwind`, and restore original stacks cleanly.
- Wipes the alternate stack memory after execution completes.
